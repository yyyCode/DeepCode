DeepCode

一个终端里的 agentic 编码助手。给它一句自然语言，它会读文件、改文件、跑命令。

引擎在每个调用点抛出一个事件，插件把自己的 hook 注册成中间件，按 tier 权威序串成一条链。 内建工具与将来的第三方插件走完全相同的接口 —— 内核里没有一张硬编码的工具表。

git clone https://github.com/yyyCode/DeepCode && cd DeepCode && pnpm install && npm link

需要 Node ≥ 20 与 pnpm。之后在任意项目目录里：deepcode "跑一下测试，把失败的那条修掉"

现场看一眼

下面这段会话按程序真实的输出形状写：提示符、工具预览、y/N、那行 [安全]， 都是固定的格式，不是我编的排版。中间两句是模型自己的话。

deepcode — ~/myproject 
> 把 dist 目录清掉
  Bash  $ rm -rf dist
执行 Bash? (y/N) y
好，dist 清掉了。
> 把这次的改动推到 main
  Bash  $ git push origin main
[安全] 一条更宽松的判定被拦下：策略里 Bash(git push:*) 要求 deny，实际得到 ask。以托管策略为准。
推不动 —— 托管策略把 Bash(git push:*) 判成 deny 了。这一条得你自己来。
  • 会写盘、会跑命令的动作，先打预览再停下等你。 按别的键都算拒绝 —— 只有 y / yes 是同意。
  • 那行 [安全] 不是提示，是拦截。 个人设置里写 allow: ["Bash"] 最多把「问一次」变成「直接做」； 托管策略里的 deny 不受影响。
  • 全程没有 --yes。 想省掉某一次询问，只能去改托管策略 —— 而托管策略必须来自文件， 没有环境变量能顶掉它。

为什么再写一个

这不是第 N 个「AI 帮你写代码」。它更接近一份能跑起来的架构答卷：把所有 agent 行为收进一张事件目录， 每个调用点抛出一个事件，插件注册的 hook 是中间件。于是「这个动作会不会被拦下、被谁拦下、拦下之后发生了什么」 能在代码里指出来，而不是靠读日志猜。

边界不靠自觉。往 contract/ 里加一个 import，pnpm lint 直接红 —— 哪一层能看见哪一层，是一张写死在脚本里的表。

做不到的事写在文档里，不藏在心里。下面「我们没做什么」一节列的就是， 包括一个会让 deny 规则安静失效的写法。

八个设计决定

每一条后面都跟着它换来的代价 —— 没有免费的纪律。

零运行时依赖

package.json 里只有 devDependencies。跑起来不下载任何东西， 也没有「上游某个包被删了」这类事故。

代价：参数解析、配置校验、unified diff、ANSI 着色，全是自己写的。

更严的永远赢

固定优先级 deny > ask > allow。规则写在哪一层、在同一数组里排第几都不影响结果 —— 重排一下配置文件不会换行为。

代价：没有「后写的覆盖先写的」，做例外得靠改托管策略。

fail-closed 到底

非 TTY（管道、CI）默认拒绝；不认识的工具拒绝；tool.check 走到链尾无人应答也是 deny，不是 allow。

为什么：方向一旦定成 fail-open，后面补不回来。

没有 --yes

有意不做自动放行开关。非交互环境里没人能按 y，那就写不了文件、跑不了命令。

谁加自动放行开关谁就是在开倒车。

个人规则掀不翻托管策略

policy 层的规则由守门器持有：跑完整条链后，若下游把策略的更严判定放宽了， 直接拿策略原文推翻它。个人 allow 的效力上限是把 ask 变成 allow。

策略层刻意没有环境变量来源 —— 一个环境变量就能改权限，等于开了个后门。

依赖边界由脚本守

pnpm lint 就是 scripts/check-boundaries.mjs：contract/ 不许 import 任何东西，builtins/ 只许 import contract/。

破坏架构不是靠 code review 拦，是直接红。

内建工具不是特例

Read / Write / Edit / Bash / Glob / Grep 与将来的第三方插件走同一条接口。模型看得见的工具清单来自注册面上 tool.call 的 matcher 取值。

内核里没有一张硬编码的工具表 —— 藏掉一个工具，是让它的 matcher 不再应答。

反向验证

每个里程碑收尾时把实现改坏一次，确认对应的测试真的会红。不红就说明那条断言是摆设， 先修断言本身。

收尾那次评审里逮到过一条「无效变异」（改坏了但行为其实没变）， 也逮到过一次「改了但钉不住」的修改 —— 后者连同理由写进了文档，没有让它看起来有覆盖。

权限：谁能放宽，谁不能

配置管连接（config.json），权限是另一套（.deepcode/settings.json）。 三组数组 allow / ask / deny，都可以省略。

权限设置的五个来源，从低到高
来源路径
user~/.deepcode/settings.json
project<工作目录>/.deepcode/settings.json
local<工作目录>/.deepcode/settings.local.json
flagdeepcode --settings=<路径>
policy托管文件，见下

policy 这一层刻意没有环境变量来源。 config.json 有，是因为「别把 key 写进文件」是真需求；权限不一样 —— 一个环境变量就能改掉权限，等于在规则引擎上开了个后门。托管策略必须来自文件：

  • Windows：%ProgramFiles%\DeepCode\managed-settings.json
  • 其它平台：/etc/deepcode/managed-settings.json

托管文件存在、却读不了或解析不了时，这一层按空处理 —— 大声警告一行， 并且在 /permissions 里标出来。这是整个设计里唯一一条 真正的 fail-open，而且消不掉：策略文件按定义是可选的，不存在时安静是对的；存在却读不了时， 「拒绝启动」对一个个人 CLI 是过度反应。看到那行警告，就是此刻没有守护。

规则的写法与含义
写法含义
Bash该工具的所有调用
Bash(git push)命令行恰好等于 git push
Bash(git push:*)命令行以 git push 开头，按空白 token 边界 —— git push origin main ✓，git pushup ✗
Read(~/.ssh/**)file_path 按 glob 匹配：* 单段、 ** 跨段
Edit(...) / Write(...)同 Read，都匹配 file_path
其它工具带括号不支持：不命中，且启动时警告一次

: 是 token 边界，不是通配符。当通配符的话，Bash(git push:*) 会要求命令里真有个冒号， 而 git push origin main 没有 —— 规则永远不命中，安静地失效。

前缀匹配不懂 shell 语法，「藏在后面」的命令它看不见。 规则比的是命令行串的开头：Bash(git push:*) 拦得住 git push origin main; rm -rf ~（开头就是 git push ）， 但拦不住 true && git push origin main —— 开头是 true，规则不命中。

所以 deny 是给手滑与误操作加的一道闸，不是反对抗手段：写得出绕开写法的东西照样绕得过去。 真要封死得靠进程权限或沙箱，那排在后面的阶段。

路径规则按绝对路径匹配（~ 会展开成主目录），相对路径不会命中。 大小写按平台原样比较，不替文件系统做归一 —— 猜错的症状是一条防御规则悄悄不命中。

更严的永远赢：deny > ask > allow。

与规则写在哪一层、在同一数组里排第几都无关。托管策略因此天然压过个人规则：它坐在 prepend，个人规则坐在 user，而个人规则掀不翻任何一条 deny。

没有 --yes，托管策略里也不写 allow。 策略说「不用问」会被当成自动放行开关，与安全底线冲突 —— 守门器只在策略更严时才插手。

会话里随时用 /permissions 看当前生效的规则、每条来自哪一层、哪些工具被隐藏、 哪些规则没生效。

一条链，没有特例

每个调用点抛出一个事件，插件把自己的 hook 注册成中间件， 按 tier 权威序串成一条链。一个 hook 可以应答 / 改写 / 拒绝 / 委托下层。

  1. prepend托管策略的守门器坐在这里
  2. user个人设置里的规则
  3. append后挂的扩展
  4. builtin六个内建工具、最小确认
  5. core没人在意时的兜底

next(e) 是 Koa 式续体，不是事件发射器：不调 next = 结束链并应答； 调 next({...e, field}) = 带改写下行。链尾只有一处，没有第二个地方可以漏。

我们没做什么，以及为什么

这一节不是免责声明。前面那些话之所以可信，就是因为这一节不藏着。

没有路径围栏

Read / Write / Edit / Glob / Grep / Bash 能碰到你进程权限内的任何路径，不限工作目录。确认提示拦的是「要不要动手」， 不是「动哪里」。

所以别在装着重要东西的机器上放它乱跑。沙箱化排在后面的阶段。

中断只杀外壳

Windows 上 Bash 经 cmd.exe 起命令，Ctrl-C 掐断的是这层外壳， 它下面的孙进程可能继续残留（没有进程组）。

没有 TUI、没有语法高亮

有 ANSI 着色与单行 spinner，但界面仍是逐行的纯文本流，也不走 ui.render 事件。

非 TTY 下 REPL 收不到输入

echo '/diff' | deepcode 这种喂法无效：readline 在 createInterface 之后就开始读，而主流程到 REPL 挂上第一个监听之间还隔着好几个 await， 管道里的行就在这段空窗里被读掉、扔了。

要脚本化请用一次性模式 deepcode "..."，那条路是好的。

/help 不反映工具隐藏

整工具 deny 会让工具从模型可见清单里消失，但 /help 仍把它列出来。要准确的去看 /permissions。

会话转录里是代码

转录落成 JSONL，放在用户级目录（不进项目目录，免得被跟着仓库提交出去）， 文件权限 0600。删掉那个文件就等于删掉那次会话 —— 没有别的副本，也不做过期清理。
