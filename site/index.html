DeepCode

一个终端里的 agentic 编码助手。给它一句自然语言，它会读文件、改文件、跑命令。

git clone https://github.com/yyyCode/DeepCode && cd DeepCode && pnpm install && npm link
deepcode "跑一下测试，把失败的那条修掉"

需要 Node ≥ 20 与 pnpm。不带参数就是交互式 REPL，--resume 接上上次的会话。

现场看一眼

deepcode — ~/myproject 
> 把 dist 目录清掉
  Bash  $ rm -rf dist
执行 Bash? (y/N) y
好，dist 清掉了。
> 把这次的改动推到 main
  Bash  $ git push origin main
[安全] 一条更宽松的判定被拦下：策略里 Bash(git push:*) 要求 deny，实际得到 ask。以托管策略为准。
推不动 —— 托管策略把 Bash(git push:*) 判成 deny 了。这一条得你自己来。
  • 要写盘、要跑命令的动作，先打预览再停下等你。按别的键都算拒绝 —— 只有 y / yes 是同意。
  • 那行 [安全] 不是提示，是拦截。个人设置里的 allow 最多把「问一次」变成「直接做」。
  • 全程没有 --yes。谁加自动放行开关谁就是在开倒车。

六个设计决定

每条后面跟着它换来的代价 —— 没有免费的纪律。

零运行时依赖

package.json 里只有 devDependencies，跑起来不下载任何东西。

参数解析、配置校验、unified diff、ANSI 着色，全是自己写的。

更严的永远赢

固定优先级 deny > ask > allow，与写在哪一层、排第几都无关。

没有「后写的覆盖先写的」；做例外得靠改托管策略。

fail-closed 到底

非 TTY 默认拒绝；不认识的工具拒绝；tool.check 走到链尾无人应答也是 deny。

方向一旦定成 fail-open，后面补不回来。

没有 --yes

有意不做自动放行开关：非交互环境里没人能按 y，那就写不了文件、跑不了命令。

谁加自动放行开关谁就是在开倒车。

依赖边界由脚本守

contract/ 不许 import 任何东西，builtins/ 只许 import contract/。

破坏架构不是靠 code review 拦，是 pnpm lint 直接红。

内建工具不是特例

八个工具走同一条接口，清单来自注册面上 tool.call 的 matcher 取值。

内核里没有一张硬编码的工具表。

一条链，没有特例

每个调用点抛出一个事件，插件把自己的 hook 注册成中间件，按 tier 权威序串成一条链。 一个 hook 可以应答 / 改写 / 拒绝 / 委托下层。

图比较宽 —— 左右滑动查看

非 TTY 默认拒绝 · 链尾无人应答 = deny · 不认识的工具 = deny；闸门坐在链的下游，任何 allow 规则都绕不过它。 指令五层里只有托管层能写；转录与历史落在用户级目录，不进项目目录 —— 免得跟着仓库一起被提交上去。

目录分层（构建时）

src/
  contract/    事件目录与契约类型 —— 不 import 任何东西
  core/        引擎：dispatch、链、tier                 → contract
  providers/   anthropic / openai 两种协议              → contract
  builtins/    六个内建工具                             → contract
  cli/         装配、REPL、渲染、设置、权限解析          → 上面全部
mods/          四个内建 mod（与第三方插件同一个接口）     → node: 内建 + contract + 自己
plugins/       第三方插件 —— 不 import 内核，只拿到注册回调

这张表就是 scripts/check-boundaries.mjs 里的规则表；方向对了才放行，破坏边界 pnpm lint 直接红。next(e) 是 Koa 式续体，不是事件发射器 —— 不调它 = 结束链并应答， 调 next({...e, field}) = 带改写下行。

41 个事件已声明，22 个已实现；八个工具里六个内建、两个由第一方插件提供 （Task / Skill）。其余 19 个事件用到时会抛 NotImplementedError —— 这是如实标注，不是「即将支持」。

权限：谁能放宽，谁不能

配置管连接（config.json），权限是另一套（.deepcode/settings.json）， 三组数组 allow / ask / deny 都可以省略。五个来源从低到高： user → project → local → flag （--settings=）→ policy（托管）。

规则的写法与含义
写法含义
Bash该工具的所有调用
Bash(git push:*)命令行以 git push 开头，按空白 token 边界 —— git pushup ✗
Read(~/.ssh/**)file_path 按 glob 匹配：* 单段、 ** 跨段
其它工具带括号不支持：不命中，且启动时警告一次

: 是 token 边界，不是通配符；路径按绝对路径匹配（~ 会展开）， 相对路径不会命中。policy 这一层刻意没有环境变量来源 —— 一个环境变量就能改掉权限， 等于在规则引擎上开了个后门，所以托管策略必须来自文件。

前缀匹配不懂 shell 语法，「藏在后面」的命令它看不见。 Bash(git push:*) 拦得住 git push origin main; rm -rf ~， 但拦不住 true && git push origin main。所以 deny 是给手滑与误操作 加的一道闸，不是反对抗手段。

个人规则掀不翻任何一条 deny（allow 的效力上限是把 ask 变成 allow），会话里用 /permissions 看每条规则的来源。

我们没做什么，以及为什么

这一节不是免责声明 —— 前面那些话之所以可信，就是因为这一节不藏着。 完整清单在 README。

没有路径围栏

六个工具能碰到你进程权限内的任何路径，不限工作目录 —— 确认提示拦的是「要不要动手」，不是「动哪里」。

别在装着重要东西的机器上放它乱跑。

沙箱不是 OS 隔离

Bash 有一道可选的路径闸，但它靠切分 token 判路径，不是解析 shell： rm $(echo /etc/passwd) 绕得过去。

加的是闸，不是墙 —— 所以它不是「可以放开权限」的理由。

没有整屏 TUI、没有语法高亮

界面是逐行的纯文本流，markdown 只认一个子集，也不走 ui.render 事件。

那棵「界面数据树」今天还没有能把它钉住的消费者。

hookify 的规则写坏了，工具会全停

算术写错、正则编译不过、钩子进程崩了 —— 一律非零退出，而 PreToolUse 上的非零就是 deny：Write / Edit / Bash 全部被拒绝，直到修好它。

我们接受这个代价 —— 一个读不懂自己规则的守卫，比一个假装没事的守卫危险。

转录里是代码

会话落成 JSONL，放在用户级目录（不进项目目录），权限 0600。 删掉那个文件就等于删掉那次会话 —— 没有别的副本。

marketplace 只做本地索引

plugin add 从一份本地索引拷插件进落点：不 fetch、不 clone、没有签名与校验和， 也没有版本与升级。

没有可信密钥体系时，做一个假的签名比不做更糟 —— 它会让人以为校验过。
