# DeepCode 项目简介

> 一个终端里的 agentic 编码助手。给它一句自然语言，它会读文件、改文件、跑命令。
> 用 TypeScript 从零写，**零运行时依赖**。

这份文档给第一次听说它的人：一页纸讲完「是什么、凭什么信它、现在到哪一步」。
细节在仓库根的 [README](../README.md) 与 [`superpowers/`](../docs/superpowers/) 里。

## 一句话

引擎在每个调用点抛出一个事件，插件把自己的 hook 注册成中间件，按 tier 权威序串成一条链：

```
prepend > user > append > builtin > core
```

一个 hook 可以**应答 / 改写 / 拒绝 / 委托下层**。`next(e)` 是 Koa 式续体，不是事件发射器 ——
不调 `next` 就是结束这条链并应答，调 `next({ ...e, field })` 就是带着改写往下走。
链尾只有一处，没有第二个地方可以漏。

于是「这个动作会不会被拦下、被谁拦下、拦下之后发生了什么」能在代码里指出来，不用读日志猜。

## 三个立得住的点

1. **一条链，没有特例。** 六个内建工具（`Read` / `Write` / `Edit` / `Bash` / `Glob` / `Grep`）
   与将来的第三方插件走**完全相同**的接口 —— 内核里没有一张硬编码的工具表；
   工具清单来自注册面上 `tool.call` 的 matcher 取值，再过白名单与 `hidden` 两道
   （`core/tool-list.ts` 是这一份清单的**唯一算法**：模型请求、`/help`、`/context` 共用它）。
2. **边界由脚本守，不靠自觉。** `pnpm lint` 就是 `scripts/check-boundaries.mjs`：
   `contract/` 不许 import 任何东西，`builtins/` 只许 import `contract/`。
   往 `contract/` 里加一个 import，直接红。
3. **fail-closed 到底。** 非 TTY（管道、CI）默认拒绝；不认识的工具拒绝；
   `tool.check` 走到链尾无人应答也是 `deny`，不是 `allow`。方向一旦定成 fail-open，后面补不回来。

## 现在能做什么

- **八个工具**：六个内建工具读、写、改文件，跑命令，找文件（`Glob`）、搜内容（`Grep`），
  加上第一方插件提供的 `Task`（派子代理）与 `Skill`（加载技能正文）。
  会写盘或执行命令的动作先打预览、停下等你按一次 `y`。
- **两种用法**：一次性 `deepcode "把测试跑一遍，失败的那条修掉"`，或者进去聊（REPL）。
- **会话**：转录落成 JSONL，`deepcode --resume` 接着上次继续（`--resume=<id>` 指定某一次）。
- **七个斜杠命令**：`/help` `/diff` `/clear` `/compact` `/permissions` `/config` `/telemetry`
  （外加 `/exit`）。
- **换 provider 不用改代码**：`~/.deepcode/config.json` 里改 `apiKey` / `baseUrl` / `model` 三样，
  Anthropic 与任何 OpenAI 兼容端点都能接。
- **可配置的权限**：五层 settings + `allow` / `ask` / `deny` 规则，`/permissions` 看当前生效了什么；
  确认提示上按 `a` 可以放行本次会话的这一类（进程内的，`/permissions forget` 忘掉）。
- **插件**：用户级目录自动装载，项目级要显式启用。还有第三种放法：`plugin add` 从一份**本地
  索引**把插件拷进落点 `~/.deepcode/installed/`，而落点不自动装载 —— **装 ≠ 启用**，
  且只有**用户级**设置能开这道闸（项目级写同一个名字不算数）。第三方插件只能拧紧不能拧松 ——
  它返回的放行判定会被丢弃，越界注册整个插件不装。`deepcode plugin list` 看装了哪些。
  仓库自带三个插件：`plugins/todo`（加了个工具）、`plugins/secret-guard`（拦下往仓库里写密钥）、
  `plugins/hookify`（把 `.deepcode/hookify.*.local.md` 里的**声明式规则**编译成 `PreToolUse`
  判定 —— 演示的是"加一套语法"，比前两个更对 P3 那一条出口标准）。
- **改配置不用开编辑器**：`deepcode config list` 看生效的每一项、值、来源（env / user / project /
  default），`deepcode config set model <名字>` 写进用户级 `~/.deepcode/config.json`。
  可写的**只有 `model`**，而它会碰的设置一个字都不碰（`config.json` 与 `settings.json` 是两份文件）。
- **可观测，但默认关着**：遥测把六个事件各记一行到用户级 `~/.deepcode/telemetry.jsonl`
  （会话开始/结束、回合一收手、每次工具结果、压缩、子代理），每行都是**零自由文本**的
  —— 字段名与字符串值必须是标识符形状，不合规整条丢掉并计数。只有**用户层**设置能打开它，
  托管层能一句话关掉。没有网络上报。`/telemetry` 看开关与本次会话写了多少行。

## 权限模型：谁能放宽，谁不能

设置来源从低到高五层：`user` < `project` < `local` < `flag` < `policy`（托管）。

- **更严的永远赢**：`deny > ask > allow`，与规则写在哪一层、在同一数组里排第几都无关 ——
  重排一下配置文件不会换行为。
- **托管策略掀不翻**：守门器跑完整条链后，若下游把策略的更严判定放宽了，直接拿策略原文推翻它。
  个人 `allow` 的效力上限，是把一次 `ask` 变成 `allow`。
- **刻意没有环境变量来源**：一个环境变量就能改权限，等于在规则引擎上开后门。
- **没有 `--yes`，也没有别的自动放行开关。** 非交互环境里没人能按 `y`，那就写不了文件、跑不了命令。
  谁加自动放行开关谁就是在开倒车。（确认提示上的 `a` 是另一回事：它只能按在一个**已经摆出来的预览**上、
  记下了什么当场打出来、只在内存里活着 —— 不是开关，见 README「安全」一节。）
- **`deny` 是给手滑与误操作加的一道闸，不是反对抗手段。** 规则比的是命令行的开头，
  `Bash(git push:*)` 拦得住 `git push origin main; rm -rf ~`，但拦不住 `true && git push origin main`。
  真要封死得靠进程权限或操作系统级的隔离；`Bash` 另有一道可选的路径闸，但它在同一个局限里。

## 已知限制（有意不做）

完整清单（每条带设计文档指路、每个"我们定的数"都标出来）在 [`已知限制.md`](已知限制.md)；
这一节只留最该先知道的那几条。

- **没有路径围栏**：能碰到你进程权限内的任何路径，不限工作目录。确认提示拦的是「要不要动手」，
  不是「动哪里」。所以别在装着重要东西的机器上放它乱跑。
- **沙箱只盖 `Bash`，而且是文本分析不是 shell 解析器**：`x=/etc/passwd; rm $x` 这类绕得过去。
  它是给手滑加的一道闸，不是反对抗手段。**没有** `dangerouslyDisableSandbox` 那种逃生阀。
- **压缩阈值是猜的**：不知道模型的真实窗口，自动压缩默认关，`/compact` 手动始终可用。自动压缩还有
  两道断电器（连失败 3 次、连压 3 次仍超阈值就停手），**那两个 3 是照抄复刻对象的数，不是我们测出来的**。
- **一轮的收场有几处是「我们定的数」，不是测出来的**：被输出长度上限截断后替它续写的上限是 **3**（与 `MAX_STOP_BLOCKS` 同一个数），每续一次都是一次**真的模型请求**（花钱，所以每次都打一行通知）；而且**没有后台工作**，也就没有挂起/唤醒 —— 一轮跑完就是跑完，子代理是同步交回结果的（不是句柄）。
- **中断只杀外壳**：Windows 上 `Bash` 经 `cmd.exe` 起命令，`Ctrl-C` 掐断的是这层外壳，
  下面的孙进程可能继续残留（没有进程组）。
- **没有整屏 TUI、没有语法高亮**：界面是逐行的纯文本流（P6 的四片都是**行内增强**，不占整屏），
  markdown 只认一个子集，代码块不着色，也不走 `ui.render` 事件（那棵界面数据树今天还没有
  能把它钉住的消费者）。
- **托管策略文件存在却读不了时，那一层按空处理**（大声警告 + `/permissions` 标出来）。
  这是整个设计里唯一一条真正的 fail-open，且消不掉 —— 看到那行警告，就是此刻没有守护。
- **插件只桥了 6 个 classic 事件**（`PreToolUse` / `PostToolUse` / `UserPromptSubmit` /
  `Stop` / `SessionStart` / `SessionEnd`）。参考实现有
  33 个事件名；其余 27 个在 `hooks.json` 里会被跳过并点名，不是静默忽略 —— 它们要的是我们
  还没有的钩子点。另外 `uses` 只在事件级别校验，细到 matcher 一级的声明**仍未做** ——
  它是 P3 预登记的一条偏差（`p3-design.md:571`），不是"排到某一阶段"。
- **hookify 的失败方向是 fail-closed，代价写在这里**：`.deepcode/` 里放一个写坏的
  `hookify.*.local.md`（frontmatter 缺字段、算子不认识、正则编译不过、文件读不动、钩子进程崩了），
  **你的 `Write` / `Edit` / `Bash` 会全部被拒绝**，直到修好或删掉它。我们接受这个代价 ——
  一个读不懂自己规则的守卫，比一个假装没事的守卫危险。**代价逐事件不同**：只有 `PreToolUse`
  上 fail 会翻成 `deny`，`PostToolUse` / `UserPromptSubmit` / `Stop` 上只是一句 `notice`。
  规则词汇也是逐事件定的，只有兑现得了的词才许写：`PreToolUse` 上是 `deny` / `ask`，
  `Stop` 上只有 `deny`，另外两个事件上只有 `notify`（往模型那边补一段话）。写 `allow` 是**错误**
  （会点名），因为插件返回的放行判定在这个框架里一律被丢弃。
- **marketplace 只做本地索引**：不 fetch、不 clone、不 HTTP。没有签名与校验和 —— 没有可信密钥
  体系时做一个假的比不做更糟。没有版本解析与升级：升级 = `remove` + `add`。
- **没有 LICENSE**（未指定许可证 / 保留所有权利）。

## 快速开始

```bash
git clone https://github.com/yyyCode/DeepCode && cd DeepCode
pnpm install && npm link            # 需要 Node ≥ 20

mkdir -p ~/.deepcode                # 配 key（也可以用环境变量 ANTHROPIC_API_KEY）
cat > ~/.deepcode/config.json <<'EOF'
{ "apiKey": "sk-ant-..." }
EOF

cd /你的项目 && deepcode "跑一下测试，把失败的那条修掉"
```
