# 已知限制

DeepCode 做不到什么、哪些数字是我们定的而不是测出来的 —— 一条不藏。

这份清单原本整段住在 README 里，现在搬到这里：README 只留会改变**「你怎么用它」**的那几条，
其余（实现细节层面的、要读设计文档才用得上的）在这儿逐条展开。**规矩是如实** ——
修掉一条就删一条，改好一条就改一条；留一条"已修"的限制与写一段"即将支持"的待办，

## 安全与权限

- **沙箱是策略层的命令分析，不是 OS 隔离**：Windows 上没有 bubblewrap / sandbox-exec 的对应物。
  候选路径的提取只有一组手写 fixture，准确率是"我们信这组 fixture"，不是"我们量过"。
  路径比较**区分大小写**（与权限规则一致）。它**只盖 `Bash`**，`Read` / `Write` / `Edit` 不在这道闸里
  （见 README「沙箱」一节）。
- **没有路径围栏**：六个工具能碰到你进程权限内的任何路径，不限工作目录。确认提示拦的是
  「要不要动手」，不是「动哪里」—— 所以别在装着重要东西的机器上放它乱跑。
- **托管策略文件存在却读不了时，那一层按空处理**（大声警告 + `/permissions` 标出来）。
  这是整个设计里**唯一一条真正的 fail-open**，而且消不掉 —— 看到那行警告，就是此刻没有守护。
- 反过来，沙箱**没有** `dangerouslyDisableSandbox` 那种逃生阀：加它等于加一个放行开关，
  与既有的那条线（「谁加自动放行开关谁就是在开倒车」）正面冲突（P4b 设计 §4）。
- **`a`（本次会话总是允许）记住的规则只在内存里，进程退出即失**，而且**不落盘**：想让它跨会话生效，
  只能自己去 settings 里写一条 `allow`（`config set` 明着拒绝 `permissions` 这个前缀）。
  撤销只有一条路 —— `/permissions forget`，一次清空全部，没有"忘掉其中一条"。
- **`a` 的粒度是刻意的粗**：`Bash` 按**归一后的那一条命令**记（不按前缀 —— `Bash(git:*)` 会把
  `git push` 一起放进来），其余工具按**整个工具**记。于是对 `Write` 按一次 `a`，意思是"这一场
  会话别再拦我写任何文件"，不只是刚才那一个路径。记了什么，按下的那一刻终端的下一行就打出来。
- **`a` 之后那一类调用不再打预览**：预览长在 `ask` 那一支上，放行就没有了 —— 这是"少按几次键"
  换来的代价。也**压不过**明写的 `ask` 规则，更掀不翻下游的 `deny`（会话里记住的规则与 settings 里
  的 `allow` 走同一条判定，效力上限仍是"把 `ask` 变成 `allow`"）。
- **转录里是代码与文件内容**：删掉那份 `.jsonl` 就等于删掉那次会话 —— 没有别的副本，也不做过期清理。

## 上下文与账本

- **压缩的阈值 `compact.atTokens` 默认 100_000 是猜的**（引擎内部看不见真实窗口）。自动压缩**默认关**，
  `/compact` 手动始终可用；摘要失败 / 返回空 / 压完反而更长 —— 三种情况都**不压缩**，出声，原文一条不动。
  自动压缩还有两道**断电器**：连续失败 3 次就停手、连压 3 次之后上下文仍然超阈值也停手（停手时会说清
  怎么恢复：`/compact` 手动再试一次、调大阈值、或关掉 `compact.auto`）。⚠️ **这两个 3 是照抄复刻对象的
  数，不是我们测出来的**（[P7 设计](../docs/superpowers/specs/2026-10-11-deepcode-p7-design.md) §5 偏差 3）。
- **截断续写的上限 3 是我们自己定的数**，不是测出来的（理由写在 `src/core/loop.ts` 的注释与
  [P8 设计](../docs/superpowers/specs/2026-10-12-deepcode-p8-design.md) §5）：于是"接几次才够"这件事
  没有依据，只有一条保险丝。
- **账本里的数字全是估的，工具那一行尤其粗**：`estimateTokens` 按 4 字符 1 token 估，中英混排会失真；
  工具那一行算的是"名字 + 描述 + schema 的 JSON 字符数"，含 `JSON.stringify` 带上来的那几个键名
  （约几十字符），**不等于**适配器真正发出的字节数（各家序列化不同）。它够用是因为账本要的是
  "离阈值还有多远"这个量级，不是精确值 —— 但别拿它当账单核。
- **`/context` 的「工具清单」那一行会很长**（工具多时逐工具全列，不截断）。这是刻意的：截断就得再编一个
  "还有 N 个没显示"，而账本的全部意义就是**不编**。`/tools` 那边反过来 —— 它截到 80 字符，
  并在同一屏说明"模型拿到的是完整的"。
- **系统提示每轮重算**（不是一个会话算一次）的代价：好处是会话中途改 `AGENTS.md` 当场生效、
  压缩之后注入面重新求值；代价是每轮多几次文件读，而且系统提示的字节可能在会话中途变化。
- **五层压缩的阈值全部锚在 `compact.atTokens` 上**（第 2–4 层取它的 80% / 85% / 90% / 95%）。
  `atTokens` 本身就是猜的，比例再整齐也还是猜的。默认值照抄 Claude Code 的形状，不是测出来的最优值；
  `pnpm bench` 量的是**同一把尺子下的相对变化**，不是"真实窗口还剩多少"
  （[P11 设计](../docs/superpowers/specs/2026-10-26-deepcode-p11-context-layers-design.md) §7）。
- **大工具结果落盘后不清理**：单个 > 50 000 字符的结果存到
  `~/.deepcode/projects/<项目>/tool-results/<会话>/`，消息里只留 2 000 字符预览。
  目录**没有容量上限、也没有过期清理**，长会话会一直累积（复刻对象有 1GB 封顶）。
  因为外置发生在工具结果**进消息列表之前**，转录里存的是预览而不是全文 —— 全文只能靠预览里
  那个路径找回。
- **第 2–4 层是读时投影**：每次请求都从完整历史重算，转录一个字不动。好处是 `--resume` 接回的
  仍是全文、不会切出孤立的 `tool_result`；代价是跨阈值时请求前缀会变，可能打断 provider 侧的
  隐式 prompt cache。
- **第 3 层（清空旧工具结果）在比例阶梯上很少出手**：第 2 层先切、切完通常已经低于 85%。
  它主要在「轮次少、结果多」与「闲置 60 分钟」两种情况下生效。这是 benchmark 的实测结论
  （三个场景里 0 命中），不是没接上；单测覆盖了它确实能清。

## 记忆

- **默认召回是关键词，不是语义**：英文按词、中文按二字滑窗匹配 `name` 与 `description`，
  换个说法、跨语言、或者描述里没写那个词，都可能召不回来。配了 `memory.recallModel` 才是让模型挑；
  关键词这一条零 API、可离线复现，但也确实比 Claude Code 默认的小模型秘书**弱**。
- **记忆是项目级的，不是用户级的**：换一个工作目录就是另一份记忆。子代理与 `Task` 内层
  **看不到**记忆注入（它的系统提示是自己那份），只在主会话里生效。
- **陈旧提醒只改变提示文本，不改行为**：超过 1 天的记忆带一句「先对照代码验证」，模型仍可能直接引用。
  `modified` 缺失时用文件 mtime 兜底；**相对日期不会被自动改写**（"周四前"就还是"周四前"）。
- **`forget` 没有回收站**：删就是删，只能重新记。索引 `MEMORY.md` 由程序生成，手改会在下一次
  save / forget 时被覆盖。
- **正文里的恶意指令没有被真正"防住"**：注入前只做两件事 —— 去掉零宽/bidi 字符、
  让伪装成 `<system-reminder>` 之类引擎标记的标签不再像真的。权限判定仍只走 `tool.check` 链，
  但一段写成自然语言的"请忽略之前的指令"是拦不住的 —— 记忆默认只由当前项目里的模型写入。
- **索引 200 行 / 25KB 之后会截断**：截断会带警告，但**不会自动合并**旧记忆；
  记忆目录被手工塞进很多文件时，只有最新的 200 个会参与扫描。

## 界面与进程

- **中断只杀外壳**：`Bash` 在 Windows 上经 `cmd.exe` 起命令，`Ctrl-C` 掐断的是这层外壳，
  它下面的孙进程可能继续残留（没有进程组）。
- **没有整屏 TUI、没有语法高亮**：界面是逐行的纯文本流，markdown 只认一个子集，代码块不着色。
  也不走 `ui.render` 事件 —— 那棵"界面数据树"的结构今天还没有消费者能把它钉住
  （[P6 设计](../docs/superpowers/specs/2026-10-11-deepcode-p6-design.md) §2.3 记了理由）。
- **没有后台工作，也就没有挂起/唤醒**：一轮跑完就是跑完，进程在等模型/等命令时不能干别的，
  子代理是**同步**交回结果的（不是句柄）。要做得先有"能等的东西"
  （[P8 设计](../docs/superpowers/specs/2026-10-12-deepcode-p8-design.md) §4 逐条记了"不追"的理由）。
- **非 TTY 环境下默认拒绝**（管道、CI）—— 所以拿它写脚本只能做只读的活。这是底线不是缺陷，
  详见 README「安全」一节。

## 子代理

- **子代理不继承指令文件**：它的系统提示只有 agent 文件里那段正文（正文为空时回落到会话的基础提示），
  `AGENTS.md` / `CLAUDE.md` 一个字都不进。这是**刻意**的硬隔离（复刻对象给了一个 `omitClaudeMd`
  旋钮，我们没有 —— 加上它必然是**放宽**），代价是子代理**不知道项目规矩**：要它守的规矩得写进
  那个 agent 文件或 `prompt` 里。
- **子代理"答偏了"看不出来**：你手里只有给它的 `prompt` 与它最后一段话；中间它读了什么、为什么这么答，
  没有独立的诊断入口（它的每一轮都派 `turn.start` / `turn.complete`，工具调用也在账上，
  但把一次答偏归因到哪一步仍然靠人读）。
- **面栈在并发 `spawn` 下会错位**：工具调用今天是串行的，所以这条路径不可达 —— 但它是**已知的**，
  不是"排到某一阶段"（[P10 设计](../docs/superpowers/specs/2026-10-12-deepcode-p10-design.md) §5 偏差 7）。
- **`spec.tools` 的效力是「父面的子集」**：一个写着 `tools: ['Bash']` 的 agent，若父级那一轮看不见
  `Bash`，它拿到的是**空面**（同上 §5 偏差 1）。
- **派一次子代理会多算一遍工具面**：`tool.describe` 因此多派一轮（纯查询，无权限影响，同上 §5 偏差 6）。

## 插件与事件

- **42 个事件里实现了 23 个**：其余 19 个已声明、未实现，用到时会抛 `NotImplementedError`。
- **插件只桥了 6 个 classic 事件**（参考实现有 33 个事件名；其余 27 个在 `hooks.json` 里会被跳过并点名，
  不是静默忽略 —— 它们要的是我们还没有的钩子点）。
- **`uses` 只在事件级别校验**：`tool.check` 这一个名字是粗粒度的，声明了它的插件对每个工具都能说上话。
  细到 matcher 一级的声明**仍未做** —— 它是 P3 预登记的一条偏差
  （[P3 设计](../docs/superpowers/specs/2026-10-11-deepcode-p3-design.md) §11），不是"排到某一阶段"。
- **marketplace 只有本地目录**：没有网络、没有签名与校验和、没有版本与升级 —— 要更新就是
  `remove` 之后再 `add`（见 README「插件」一节）。
