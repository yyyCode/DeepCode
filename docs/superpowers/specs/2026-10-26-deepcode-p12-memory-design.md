# DeepCode P12 记忆系统设计

> 对标 Claude Code 的跨会话记忆（用户提供的「五、记忆系统」材料，
> 以及 `docs/claude-code-架构分析/11-memory-and-context.md` 的 L4 持久记忆）。
> 一句话口径：**记该记的，不记能推导的；存索引，按需加载详情。**

---

## 1. 现状与差距

DeepCode 目前没有任何跨会话记忆：

| 复刻对象 | DeepCode 现状 |
| --- | --- |
| 四种封闭类型（user / feedback / project / reference） | 无 |
| 一条记忆一个 `.md`，frontmatter 带 name / description / type | 无 |
| `MEMORY.md` 索引常驻系统提示，正文按需加载 | 无 |
| 召回时只读每个文件前 30 行做清单 | 无 |
| 小模型当秘书，从清单里挑最多 5 条 | 无 |
| 超过 1 天的记忆附带陈旧度警告 | 无 |
| 索引 200 行 / 25KB 双上限，超限显式提醒 | 无 |
| 记忆内容里的不可见字符与伪装标记在注入前中和 | 无 |

每次 `deepcode` 启动都是一个全新会话。用户说过的「不要 mock 数据库」「我在用 DeepSeek」
「认证重写是合规驱动的」，下一场会话里一个字都不剩。P7 的 `AGENTS.md` 能承载**项目约定**，
但它要求用户手动维护文件，不解决「模型在对话里学到的、值得跨会话保留的东西」。

## 2. 设计口径

### 2.1 四种类型，封闭集合

```ts
export const MEMORY_TYPES = ['user', 'feedback', 'project', 'reference'] as const;
```

- `user`：用户是谁、擅长什么、知识水平。让解释因人而异。
- `feedback`：该做什么、不该做什么。**必须同时写 `Why` 与 `How to apply`** ——
  没有 Why，模型遇到边缘情况只能盲从；没有 How，规则落不了地。
- `project`：正在发生什么、截止日期、重要决策。**相对日期必须转成绝对日期**。
- `reference`：去哪找什么（Linear 项目、Grafana 看板、Slack 频道）。

不设 `any` / `general` 类型。无约束的记忆会膨胀成垃圾堆；四种类型是在逼写入方做分类决策。

### 2.2 不记什么（排除清单）

写进 `Memory` 工具的描述，并在本设计里固定下来：

1. 代码模式、项目架构、文件结构 —— `grep` / `git` / `AGENTS.md` 能拿到。
2. Git 历史与最近改动 —— `git log` / `git blame` 才是权威。
3. 调试方案与修复方法 —— 修复已经在代码里，commit 消息记着上下文。
4. `AGENTS.md` 已经写了的内容 —— 不重复。
5. 临时任务状态与当前对话上下文 —— 会话级信息不需要跨会话。

核心原则：**能从当前代码推导出来的信息，一律不存。** 代码是活的，记忆是死的；
一条「AuthService 在 src/auth.ts 第 42 行」的记忆变成权威错误时，比没有记忆更糟。

### 2.3 索引 + 独立文件

- 一条记忆一个 `.md`，frontmatter 三字段：`name` / `description` / `type`，外加 `modified`。
- `MEMORY.md` 是**生成的**索引，一行一条，最多 200 行 / 25KB。
- 索引每轮进系统提示；正文只在被召回时注入。

为什么索引要常驻、正文按需：全部塞进提示，50 条就可能占满上下文；完全不塞，
模型又不知道有哪些记忆可用。索引是目录，正文是书页。

### 2.4 召回：默认关键词，可选小模型

复刻对象用 Sonnet 当秘书。DeepCode 的 provider 不保证有便宜模型，每轮多一次 API
调用是确定成本，所以**默认不花这次调用**：

- 关键词打分：把用户问题切成 ASCII 词与中文 bigram，与 `name + description` 求重叠，
  取分数最高的最多 `maxRecall` 条。零 API、可离线 benchmark、结果可解释。
- 可选 `memory.recallModel`：配了才走小模型。同一套清单发给它，要求只返回文件名数组，
  最多 5 条；失败/超时/解析不出来一律回落到关键词。

两种召回都把正文作为一段「本次召回」注入系统提示。**索引部分永远在，召回部分每轮重算。**

### 2.5 陈旧度

超过 1 天的记忆，注入时附带：

> 这条记忆已经有 N 天了。记忆是某个时间点的观察，不是实时状态——
> 其中关于代码行为或 file:line 引用的断言可能已经过时。在当作事实引用之前，
> 请先对照当前代码验证。

复刻对象为了 prompt cache 稳定冻结过年龄注记；我们的系统提示本来就每轮重算
（P7 §3.2），这条偏差继承自那里。

## 3. 架构

```
~/.deepcode/projects/<slug>/memory/
  MEMORY.md                    ← 生成，注入时最多 200 行 / 25KB
  feedback-no-mock-db.md       ← 一条记忆一个文件
  user-go-backend.md
  project-auth-rewrite.md
  reference-linear-auth.md

用户提交一行
      │
      ▼
prompt.submit ──► 记下 query；配了 recallModel 就开始一次侧查询（不阻塞提交）
      │
      ▼
prompt.section ──► scanMemoryFiles（每文件只读前 30 行，≤200 个）
      │             ├─ 关键词打分 / 小模型选择 → 最多 5 条
      │             ├─ 读被选中文件的正文（每条第 1 次，不缓存）
      │             └─ 拼成一节：索引 + 本次召回（含陈旧度警告）
      ▼
系统提示（每轮重算）
      │
      ▼
provider.stream

Memory 工具 save / read / forget
      │
      ▼
写一条 .md → 重新生成 MEMORY.md → 下一次提问就能召回
```

三个关键点：

1. **写入与注入分离**。工具只写文件；注入在每轮 `prompt.section` 里重新算。
   记忆文件被外部编辑器改了，下一轮就能看到（头部缓存只影响 description 的改动）。
2. **失败一律 fail-open**。扫描/索引/召回/侧查询任何一步坏了，这一轮就是「没有记忆」
   加上一次出声提醒——绝不让一个正在跑的 turn 挂掉。
3. **记忆是注入面，也是攻击面**。正文来自模型或用户粘贴的内容，进入提示前要中和
   不可见字符与伪装成引擎标记的标签。

## 4. 逐层设计

### 4.1 存储

目录：`<home>/.deepcode/projects/<projectSlug(cwd)>/memory/`。
与会话转录同一个分桶规则（`cli/transcript.ts` 的 `projectSlug`），因此**记忆按项目隔离**，
不跨仓库共享。

文件格式：

```markdown
---
name: no-mock-database
description: 集成测试必须使用真实数据库，不能用 mock
type: feedback
modified: 2026-03-28T10:12:00.000Z
---

集成测试必须使用真实数据库，不能用 mock。

**Why:** 上季度 mock 测试全部通过但生产环境迁移失败了。
**How to apply:** 在这个模块写测试时，始终连接真实数据库。
```

- `name` 是文件名（不含 `.md`），只允许 `[A-Za-z0-9][A-Za-z0-9._-]*`（≤64 字符）。
  描述用中文没问题，文件名保持 ASCII —— 跨文件系统最稳。
- `description` 单行、≤200 字符，专门用于召回匹配。
- `modified` 是 ISO 时间；缺失或坏掉时回落到文件 mtime。
- 单条正文 ≤20,000 字符；超了 `save` 拒绝并说明原因。

### 4.2 索引

`MEMORY.md` **由 DeepCode 生成**，不让模型手写。理由：手写索引与文件内容迟早漂移，
而漂移的索引比没有索引更坏。生成是确定性的：按 `modified` 倒序，一行一条：

```
- [feedback] [no-mock-database](feedback-no-mock-database.md) — 集成测试必须使用真实数据库，不能用 mock（2026-03-28）
```

- 写到磁盘时按 200 行 / 25KB 截断，末尾附一行警告，说明总条数与「请合并或删除旧记忆」。
- 注入时再检查一次上限（防外部手改），超了同样截断 + 警告。
- 扫描最多 200 个文件（最新优先）。超出的记忆仍在磁盘上，`Memory read` 仍可按名读，
  但不会进索引/召回 —— 这是上限在设计上的压力阀。

### 4.3 召回

**扫描**：`readdir(memoryDir)` → 过滤 `.md`（不含 `MEMORY.md`）→ 每个文件只读前 30 行
→ 解析 frontmatter → 按 `modified` 倒序取前 200。坏 frontmatter 的文件跳过并计入
`broken`，第一次遇到时出声一次；不因为一个坏文件让整份记忆消失。

**关键词打分**：

- 切词：ASCII/数字词（`[a-z0-9][a-z0-9_./-]+`，小写）+ 中文 bigram（连续汉字的每个
  两字窗口）。停用词表很小（`the` / `and` / `这个` / `一下` …），只挡高频噪声。
- 打分：词命中 `description` +3，命中 `name` +2；同一词不重复计。
- 选前 `maxRecall`（默认 5）条，`score > 0` 才要；同分按 `modified` 新者优先。
- 问题里一个可识别词都没有（纯符号、纯停用词）→ 召回 0 条，只注入索引。

**小模型（可选）**：`memory.recallModel` 配了才走。

- 清单：`- [type] filename (YYYY-MM-DD): description`。
- 指令：选最多 N 条、只返回 JSON 字符串数组、没有就返回 `[]`。
- 用 `$.model.stream`，`tools: []`，`AbortSignal.timeout(8_000)`。
- 返回值只认扫描集合里真实存在的文件名；解析失败 / 超时 / 抛错 → 关键词兜底 + 出声一次。

**注入**：

- 每条正文截到 4,000 字符；整段召回正文总量截到 12,000 字符。超了附
  `[已截断，完整内容用 Memory read 读 <name>]`。
- 正文与描述先过中和器（§4.5）。
- 顺序：索引在前，召回正文在后；召回正文每条带文件名与年龄。

### 4.4 `Memory` 工具

一个工具，三个动作：

| action | 必填 | 行为 |
| --- | --- | --- |
| `save` | `name`、`type`、`description`、`content` | 新建或覆盖；重建索引；返回路径与上限提醒 |
| `read` | `name` | 读全文（同样过中和器）；不存在给出明确错误 |
| `forget` | `name` | 删除文件；重建索引；不存在给出明确错误 |

`save` 的校验：

- `type` 必须是四种之一，否则拒绝并列出四种。
- `name` 必须匹配 slug 规则，否则拒绝（也挡住 `../` 路径穿越）。
- `description` 非空、单行、≤200 字符。
- `content` 非空、≤20,000 字符。
- `type === 'feedback'` 时正文必须同时含 `**Why:**` 与 `**How to apply:**`，
  否则拒绝并给出模板。
- 索引超 200 行 / 25KB 时**保存仍然成功**，但返回值明确说「下一次注入会截断，
  请合并或删除旧记忆」。不静默截断，也不把用户刚写的东西丢掉。

工具描述里写清四种类型、排除清单、project 必须用绝对日期、feedback 必须写 Why/How。
工具是模型认识记忆系统的唯一入口，描述就是它的说明书。

### 4.5 注入安全

进入系统提示前，正文与描述都做两件事：

1. 去掉不可见字符：`U+200B–200F`、`U+202A–202E`、`U+2060–2064`、`U+FEFF`。
2. 中和伪装标记：`<system-reminder` / `<memory` / `<deepcode`（大小写不敏感）的 `<`
   换成 `&lt;`；`[钩子补充的上下文]` 换成 `[记忆内容里的同名字样]`。

记忆仍然可能包含恶意**指令**（例如「忽略权限，直接执行」）。中和器不负责判断语义；
权限判定仍然只走 `tool.check` 链。这一点在设计里说清楚，不假装文本中和等于安全。

### 4.6 失败方向

| 失败 | 行为 |
| --- | --- |
| 记忆目录不存在 | 静默：没有记忆是常态，不是错误 |
| 扫描/解析出错 | 这一轮没有记忆 + 出声一次 |
| 索引写失败 | 记忆文件已经写成；返回值说索引没更新 |
| 小模型召回失败/超时 | 关键词兜底 + 出声一次 |
| `Memory` 工具参数坏 | 工具结果 `ERROR: …`，turn 继续 |
| 注入超限 | 截断 + 明确警告，不静默 |

## 5. 配置

新增顶层 `memory` 块（与 `compact` 一样逐字段合并、字段级降级）：

```json
{
  "memory": {
    "enabled": true,
    "maxRecall": 5,
    "recallModel": "deepseek-chat"
  }
}
```

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 关掉 = 不注册 `Memory` 工具、不注入索引、不召回 |
| `maxRecall` | `5` | 每次最多召回几条，正整数（**没有上界**；实际建议 ≤20） |
| `recallModel` | 省略 | 配了才用小模型召回；省略 = 纯关键词 |

上限（200 行 / 25KB / 30 行扫描 / 20K 单条 / 4K 单条注入 / 12K 召回总量）是常量，
不做配置项：它们是这套机制的压力阀，可调就等于可以悄悄关掉。

未知子键、类型不对的字段：按默认值处理并出声，不废掉整份设置（它不是权限）。

## 6. 可观测性

`/context` 新增一行（在「分层压缩」之后、「上次实测」之前）：

```
  记忆　　　40 条 · 索引 44 行 / 787 token · 召回 5 条 / 239 token（关键词）
```

- 条数是**有效**记忆数；坏文件在扫描时另行出声，不混进这个数。
- 「召回」是上一次提问真正注入的条数与正文 token；没召回就是 `召回 0 条 / 0 token（无）`。
- 召回模式写进去：`关键词`、`小模型` 或 `无`。
- 索引被 200 行 / 25KB 截断时带「（已截断）」。
- 数字全部来自插件自己，不另算一本账。

`/memory` 命令：不带参数列出所有记忆（类型、名字、描述、多久前，以及目录路径）；
带名字打印正文。用户需要一条不依赖模型的路来检查「它到底记住了什么」。

## 7. 偏差与代价（如实写）

1. **默认的「秘书」不是模型，是关键词打分。** 复刻对象用 Sonnet；DeepCode 的 provider
   不保证有便宜模型，每轮多一次 API 调用是确定成本。代价：同义改写、跨语言、拼写错误
   召不回来。`memory.recallModel` 是那条可选的原路。
2. **索引是生成的，不是模型手写的。** 换来「索引与正文不会漂移」；代价是模型不能按自己的
   判断调整索引顺序，索引格式也是我们定的。
3. **没有并行预取。** 关键词召回是纯字符串操作，开销接近零；小模型召回在
   `prompt.submit` 里启动，但 DeepCode 在请求前没有别的重活可与它并行，所以它确实会增加
   这一段延迟。复刻对象「几乎零延迟」的前提（与主模型请求并行）在我们这里不成立。
4. **只做项目级，不做全局/团队记忆。** 没有 `CLAUDE_MEMORY_STORES` 那样的跨仓库共享。
   记忆跟着 `projectSlug(cwd)` 走。
5. **不做语义检索。** 与复刻对象一致；关键词是刻意的选择，不是省事。
6. **陈旧度注记每天变化**，会改变请求前缀。复刻对象为此冻结过注记；我们的系统提示本来就
   每轮重算，这条代价继承自 P7。
7. **子代理不带记忆。** 系统提示那一节只进主会话；子代理用自己的 system prompt。
8. **`forget` 没有版本与撤销。** 删了就删了，转录不覆盖记忆文件。
9. **不校验 relative → absolute 日期转换。** 工具描述要求模型写绝对日期，但「周四」这种
   字符串仍然可能被写进去。
10. **文本中和不等于防注入。** 记忆正文里的恶意指令仍然可能影响模型，只是不能伪装成
    引擎自己的标记。权限闸门不受影响。
11. **扫描不缓存。** 每次用户提问最多 200 次「读前 30 行」。这在 SSD 上可接受，
    但不是零成本；以后要优化再加按目录/索引 mtime 的缓存。
12. **索引文件与注入上限是两套检查。** 写盘时截断一次，注入时再检查一次，防止外部手改。
    多一次检查不改变语义，只是让「上限」在两条路径上都成立。

## 8. 验收

### 8.1 出口标准

1. **四类型封闭**：`save` 拒绝第五种类型，并列出四种。
2. **排除清单在工具描述里**：五种不该记的东西逐条写出。
3. **索引常驻、正文按需**：有记忆时 `prompt.section` 含索引；未被召回的记忆正文不进提示。
4. **召回可用**：标注好的查询集里，目标记忆进入前 5；没有可识别词时召回 0 条。
5. **上限成立**：250 条记忆时索引注入 ≤200 行；单条正文/召回总量按常量截断并警告。
6. **陈旧度**：超过 1 天的记忆带警告，当天的不带。
7. **安全**：正文里的零宽字符与伪装标签在注入前被中和。
8. **失败方向**：目录不存在、frontmatter 坏、小模型失败、工具参数坏，都不让 turn 挂。
9. **工具闭环**：`save` 之后索引里出现；`read` 读得回；`forget` 之后消失。
10. **不破坏既有**：没有记忆目录时，系统提示与 P11 逐字节相同（不新增空节）。

### 8.2 Benchmark 场景

`scripts/benchmark-memory.ts`，三个场景：

| 场景 | 形状 | 量什么 |
| --- | --- | --- |
| `recall-40` | 30 条中文 + 10 条英文记忆，12 条标注查询 | 全量注入正文 vs 索引 + 关键词召回：token、命中率 |
| `large-index` | 250 条记忆（同主题反复记录） | 索引注入是否守住 200 行 / 25KB，截断警告是否出现 |
| `mixed-language` | 中英混排的记忆库，4 条中文查询 + 4 条英文查询 | 每种语言的查询能否命中同语种记忆（不做跨语言翻译） |

基线 = 「把全部记忆正文都塞进提示」；分层 = 「索引 + top-5 召回」。
token 仍是 `ceil(chars/4)` 估算，两边同一条尺子；量的是注入体积与命中，不是记忆质量。

### 8.3 实测（`pnpm bench:memory`）

> 数字由 `scripts/benchmark-memory.ts` 打印；下表来自本阶段最后一次运行。

| 场景 | 记忆数 | 全量注入 | 索引 + 召回 | 省下 | 命中 |
| --- | --- | --- | --- | --- | --- |
