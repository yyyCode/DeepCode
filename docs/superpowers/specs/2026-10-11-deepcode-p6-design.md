## 0. 决策摘要

| # | 决策 | 一句话理由 |
| --- | --- | --- |
| 1 | 切四片：**P6a 活动面 → P6b 内容面 → P6c 改动面 → P6d 输入面** | 可见性是最缺的那一块（今天工具结果用户一个字都看不到），内容面要在它之上（活动行与正文抢同一块屏幕），改动面复用内容面的着色与折行，输入面碰的是 readline —— 与渲染是两块风险，放最后单独一片 |
| 2 | 形态是**行内增强**，**不做 alternate screen** | 保住终端原生滚动与复制粘贴（复制报错、粘贴代码是编码助手的刚需）；非 TTY 下逐字节不变这条既有不变量天然继续成立；参考实现（Claude Code）就是这么做的 |
| 3 | **零新增事件** | 活动面要的每一件事都已经在事件目录里：`turn.start/step/complete`、`tool.check`（含 `ask`）、`tool.call`（可包裹 → 起止与耗时）、`tool.result`（`ok` + `output`）、`agent.spawn`、`session.compact`。于是 **UI 是插件，不是内核分支** |
| 4 | **不扩调色板**，仍是今天那 5 个语义（`bold`/`dim`/`red`/`green`/`cyan`） | 界面元素要的是**语义稳定**，不是颜色多。加一个颜色的代价是每个渲染点都要重新回答"这个该用什么色" |
| 5 | 「渲染第一次对插件可见」这条**实质**兑现，**不以 `ui.render` 数据树的形式** | P3 偏差 2 那条欠账继续持有（消费者仍然只有一个 surface），但它的实质要求——渲染是一条所有人都能挂上去的路——本片用"既有事件的观察者"兑现。见 §2.3 |
| 6 | 三条硬规矩：**TTY / 管道两条路**（管道逐字节不变）、**摘要 ≠ 回模型的正文**、**`src/core/**` 不改** | 第一条是既有纪律的延续（`spinner` 非 TTY 下已经是一个字节都不产出）；第二条是两个消费者两条口径；第三条是"UI 是插件"的可验证形式 |
| 7 | 顺手修**两个真缺陷**，不算新功能：`main.ts` 的 `warnLine` 绕过渲染器、非 TTY 下 REPL 收不到输入 | 前者会让警告粘在 spinner 那半行后面；后者已经写进 README「已知限制」，是这一片唯一该现在修的既有欠账 |
| 8 | 历史文件 `~/.deepcode/history` 走**和 transcript 同一条安全规矩**（用户级 home、0600） | 历史里装的是用户敲过的话，与转录一样**含代码**。规矩定过一次就得一以贯之，不能因为"这只是输入"就放项目目录 |
| 9 | 确认框**只强化、不弱化**：预览上色、写清具体动作与落点，但 `y/N` 与 fail-closed 一个字不改 | 项目底线。`--yes` 仍然不存在，这一片也**不新增**任何自动放行开关 |
| 10 | 验收沿用 P2/P4/P5：**按检查点批量做，任务级只跑 `pnpm typecheck`**，每片做反向验证 | 用户的长期指令，也是前四个阶段跑通的节奏 |
| 11 | 提示语里出现的键**必须真的能用**（今天只接了 `Ctrl-C`，那提示就写 `Ctrl-C`，不写 `esc`） | 提示骗人比没有提示更坏，与"不给一份看着像真的的假清单"是同一条 |
| 12 | 不做进度条 | 我们**没有**可靠的进度来源。假进度条比没有进度条更坏 —— 它把"我不知道还有多久"伪装成一个数字 |

## 1. 出口标准怎么落

P6 是新阶段，§9.3 里没有它的行。本节先定四条，然后写进上位文档（§9，随本片一起改）。

| # | 出口标准 | 落在哪片 | 怎么验（可执行的判据） |
| --- | --- | --- | --- |
| 1 | 执行过程中终端**看得见**每个工具的开始、结束、耗时与结果摘要；同一条命令**管道出去逐字节与今天相同** | P6a | TTY 侧：一个 pty 夹具跑脚本化 provider，断言输出里出现 `⏺ Bash`、`⎿`、耗时与截断标记；管道侧：同一条命令 `\| cat` 出去，与**改动前录下的快照逐字节相同** |
| 2 | 工具结果在终端**被截断**，回给模型的是**完整原文** | P6a | 两个断言同时存在：一个数终端行数与 `… 还有 N 行`，一个读 `messages` 里的 `tool` 消息确认是全文。任一条单独存在都不算 |
| 3 | 这一阶段 **`src/core/**` 没有行为改动**（UI 是插件不是内核） | 全片 | 一条脚本断言 `git diff --stat <基线>..HEAD -- src/core` 为空；若某片发现非改不可，**先记成预登记的偏差**（§8）再动，不许悄悄改 |
| 4 | `NO_COLOR` / `TERM=dumb` / 拿不到宽度时全部**降级为人话**，不留残缺框线 | P6b、P6c | 一组环境变量矩阵下的输出断言；判据是"降级后的输出里不出现任何框线字符" |

**为什么第 3 条值得当出口标准**：这个项目的立身之本是"一条链，没有特例"。如果界面是靠往内核里加分支做出来的，那这句话就是假的 —— 而假话在文档里没有任何成本。把它写成一条能跑红的断言，是让这句话有成本的最便宜办法。

## 2. 口径

### 2.1 什么叫"行内增强"

三条**不许**：

- 不申请 alternate screen（`\u001b[?1049h` 这个序列不出现在代码里）。
- 不接管全屏，不自管滚动，不画边框把整个屏幕框起来。
- 不用鼠标相关序列。

三条**许**（光标动作白名单，就这三种）：

| 序列 | 干什么 | 用在哪 |
| --- | --- | --- |
| `\r` | 回到本行行首 | 重画活动区 |
| `\u001b[K` | 从光标抹到行尾 | 擦掉旧的一帧 |
| `\u001b[<n>A` | 上移 n 行 | 多层活动区（状态行 + 进行中的工具） |

**核心概念：活动区是一块"借用"的区域，不是持久 UI。** 它只活在一次动作期间（一次模型往返、一次工具执行、一次等确认），动作一结束就**落地成一行永久记录**：

```
  转着的（临时，随时被擦）            落地后（永久，进滚动历史）
  ⏺ Bash  pnpm test · 3.2s    →      ⏺ Bash  pnpm test
                                       ⎿  12 行输出 · 退出码 1 · 3.2s
```

这条区分是整片的地基：**永久记录走 stdout 的普通写入，活动区走活动区管理**。前者是转录，后者是仪表盘。混在一起的后果今天已经能看见 —— `spinner` 必须在自己擦掉之前先想一遍"有没有半行小圆圈粘在提示符前面"，而那个判断散在每个调用点（`render.ts` 里三处、`prompt.ts` 一处、`main.ts` 一处漏了）。

**活动区最多 3 行**：状态行 1 行 + 最多 2 个"正在进行"的行（子代理嵌套时用得上）。超出的折叠成 `… 还有 N 个进行中`。

### 2.2 两条路的契约

```
TTY（process.stdout.isTTY）        →  活动面 + 着色 + 折行 + 截断
管道 / 重定向 / CI（非 TTY）        →  与今天逐字节相同
```

"逐字节相同"不是形容词，是一条**回归网**：改动前先录一份非 TTY 快照（脚本化 provider 的完整 stdout+stderr），P6 每一片跑完都对一遍。今天 `test/cli.test.ts:82` 的 `expect(written()).toBe('改好了')` 就是这条网的一个网眼。

`NO_COLOR` / `TERM=dumb` **在 TTY 下也只关颜色**，不关活动面（它们是两种不同的降级，`colorEnabled` 已经只回答颜色那一个问题）。

### 2.3 与 `ui.render` 的关系（P3 偏差 2 的处置）

P3 把"不做 `ui.render` 数据树"排到 P4，P4 没做，P5 也没做。本轮**判掉这笔账**，但判法要说清：

- **不做**：数据树 + `$.ui.resolve` 逐 surface 元素表。理由与 P3 时一样 —— 它存在的意义是**多个消费者**（terminal / desktop / mobile），而我们仍然只有一个。按本项目自己的 YAGNI 判据，它今天还是白建。
- **做**：偏差 2 的**实质**要求 —— "渲染第一次对插件可见"。本片的做法是：**每一个界面元素都是既有事件的观察者**（活动行挂 `tool.call`/`tool.check`、结果摘要挂 `tool.result`、耗时挂 `turn.start`/`turn.complete`、嵌套挂 `agent.spawn`），第三方插件用**完全相同**的事件看到**完全相同**的信息。这就是"没有特例"在界面这一层的落地。

于是 §9.2 矩阵里 UI 那一格与 §10 偏差 1 的那句"P3 补上"都要改（§9）。

## 3. P6a 活动面：「正在做什么」

这是用户点名的那一条，也是今天最大的空洞 —— **工具执行期间屏幕上什么都没有**。Bash 跑 30 秒，spinner 早停了，用户面对一块静止的屏幕，唯一的线索是"它好像还没回来"。

### 3.1 五种活动行

| 状态 | 触发 | 样子 |
| --- | --- | --- |
| 想 | `turn.start` → `turn.step` 第一个增量前 | `⠹ 思考中… · 1.2s` |
| 做 | `tool.call` 进入（包裹前） | `⏺ Bash  pnpm test · 3.2s` |
| 等 | `tool.check` 返回 `ask` | `⏺ Edit  src/parse.ts` + 下一行 `⏸ 等你按 y（其余键取消）` |
| 派 | `agent.spawn` | 状态行换成子代理的名字，**缩进一层**显示它内部的工具 |
| 压 | `session.compact` | `⠹ 压缩上下文中…`（今天只有一个 spinner 标签，压不出区别） |

耗时字段**只在 ≥ 1s 时出现**。低一秒的动作刷出一串 `0.1s 0.2s 0.3s` 是噪音，而且会让每一帧都不同宽 —— 在终端里就是抖动。

状态行右端有一句 dim 的 `Ctrl-C 中断`（窄屏时**它先被砍**）。今天的中断确实接在 `Ctrl-C` 上（`turns.onSigint`），所以提示写的键是真的 —— 这正是决策 11 那条规矩：**`esc` 只有在真的接上之后才许出现在提示里**。

### 3.2 一个完整回合长什么样

```
> 把测试跑一遍，失败的那条修掉

⏺ 我先看看测试是怎么跑起来的。

⏺ Read  package.json
  ⎿  读到 24 行

⏺ Bash  pnpm test
  ⎿  12 行输出 · 退出码 1 · 3.2s
     FAIL  test/parse.test.ts > 空输入
     expected 'x' to be 'y'
     … 还有 9 行

⏺ Read  src/parse.ts
  ⎿  读到 84 行

⏺ Edit  src/parse.ts
  ⎿  +3 −1

⏺ Bash  pnpm test
  ⎿  4 行输出 · 退出码 0 · 2.8s

测试过了。改的是 src/parse.ts:41 那个空串分支。
```

对照今天：上面这段里**除了两行模型的话，别的今天一个字都不会出现**。四行 `⏺` 与其下的 `⎿` 全是新东西。

`⏺` 与 `⎿` 两个符号都是有意的：前者一个字符宽、区分度高、在等宽字体里没有歧义；后者（U+23BF）在参考实现里对同一个位置，且它是**唯一**那个能一眼看出"这行是从属信息"的通用字符。

### 3.3 结果摘要的截断规则

| 项 | 值 | 理由 |
| --- | --- | --- |
| 最多行数 | 6 | 一屏 24–40 行，一次工具活动不超过它的 1/4 |
| 每行最多字符 | 200 | 超过就该折行，而摘要**刻意不折**（折行是内容面的事） |
| 尾部标记 | `… 还有 N 行` | 用 `…` 不用 `...`：一个字符宽，宽度计算不漂（与 spinner 标签同一条理由） |
| 首行特例 | 报错时优先给 `ERROR:` 那一行 | 工具失败的正文以 `ERROR:` 开头（`loop.ts` 那条既有判据），那是用户最想先看到的一行 |

**摘要是给人看的，不是给模型看的。** `tool.result` 的 `output` 原样回喂模型（截断会让模型以为工具真只输出了 6 行），终端上印的是它的截断版。这条契约有测试分别钉住两边。

### 3.4 顺带修的缺陷：`warnLine` 绕过渲染器

`main.ts` 里的 `warnLine`（以及若干处 `process.stderr.write`）**直接写 stderr**，不经过渲染器。于是任何一个警告都可能糊在 spinner 那半行后面：

```
⠹ 思考中…⚠️ 托管策略钉住了出网位置：baseUrl
```

今天没炸是因为这些警告大多发生在 spinner 起来之前。收成 `render.notice` 是一行的事，但**它必须收**：活动区一旦变成多行，散在外面的写入口每一处都是一个新的残影来源。

### 3.5 判据

1. 脚本化 provider 的一次会话里，终端输出含 `⏺ Bash`、`⎿`、`退出码`、`… 还有`（pty 夹具）。
2. 同一条会话管道出去，与基线快照**逐字节相同**。
3. `tool.result` 的截断版与全文版同时被断言（出口标准 2）。
4. **反向验证**：把截断上限从 6 改成 600，第 3 条的终端侧断言必须红。

## 4. P6b 内容面：「说了什么」

### 4.1 markdown 子集：认哪些、不认哪些

| 认 | 不认（**原样输出**） |
| --- | --- |
| `#` / `##` / `###` 标题（加粗 + 上下留白） | 表格 |
| `-` / `*` / `+` / `1.` 列表（含缩进的二级） | 嵌套引用块 |
| 围栏代码块 ```` ```lang ````（左边框 + 语言标签） | HTML 标签 |
| 行内 `` `code` ``（cyan） | 图片 `![]()` |
| `**粗体**` / `*斜体*` | 脚注、定义列表、任务列表的勾选框 |
| `> 引用`（dim） | 链接的 URL（**只留文字**，不印 URL） |

**硬规则：不认识的语法一个字都不许吃掉。** markdown 渲染最典型的 bug 是把代码里的 `a_b_c` 或 `2 * 3 * 4` 当强调吃掉字符 —— 对一个编码助手来说，这是**改坏用户看到的代码**。所以：
- 强调的定界符必须**成对、行内、且紧贴非空白字符**（开定界符后面不能是空白，闭定界符前面不能是空白）—— 这条就是让 `2 * 3 * 4` 全身而退的那一条，也是 CommonMark 左右侧翼规则的简化版；`a_b_c` 那种词中定界符**一律不认**；
- 代码块、行内码里的内容**逐字节原样**，不做任何替换（强调、列表、标题都不认）；
- 认不出来时**原样输出**，宁可少渲染一个标题，也不许多吃一个字符。

这条也是判据：一组"会吃掉字符"的输入（`a_b_c`、`**`、`费用 * 2 * 3`、未闭合的 ``` 、`|表格|`）逐条断言输出**与输入逐字节相同**。

### 4.2 流式：按行缓冲

`turn.step` 是**增量**，而 markdown 的结构单位是行与块。做法：

- 增量先拼进一个**行缓冲**；
- 只在 `\n` 处切行，**完整的行**才渲染；行尾没结束的部分留在缓冲里；
- 围栏代码块的状态跨行保持（未闭合 → 按代码块渲染到底，闭合时补上右下的尾巴）；
- 缓冲按 code unit 拼，**永不按长度切** —— provider 按字节切块时，一个多字节字符被切成两半是常态，按长度切会把它切坏。

代价：行内强调要等这一行打完才上色。这是**正确的取舍** —— 逐字上色意味着每收到一个字符就要重新解析一遍整行，而收益只是"粗体晚半秒变粗"。

### 4.3 宽度与折行

- 宽度来源 `process.stdout.columns`；**只在 TTY 下**取，拿不到就当 80。
- 非 TTY 恒不折（逐字节不变的直接后果）。
- 中文算 2 列 —— 需要一个 `displayWidth()` 助手。**只做"宽 / 窄 / 零宽"三档**，不做完整 Unicode 表：覆盖 CJK 区间、全角标点、组合附加符与零宽字符即可。
- 代码块**不折**（保真优先）；超宽时整块按宽度截断并按 §3.3 的规则标注行数。
- 表格里那几类"折了也没法看"的东西（表格、长 URL）本来就原样输出，不参与折行。

**登记这条的代价**：emoji 的 ZWJ 序列、变体选择符、以及少数区间外的宽字符会算错一列。接受 —— 算错一列的后果是一个框线歪一格，而为此引一张完整 Unicode 表（或一个依赖）不划算。

### 4.4 判据

1. §4.1 那张"必须逐字节不变"的清单。
2. 中文标题 + 围栏代码块在 60 / 80 / 120 三个宽度下的框线对齐（按 `displayWidth` 断言，不是按字符数）。
3. 流式：把一段带未闭合代码块的文本**按一个字符一块**喂进去，输出与整段喂进去**逐字节相同**。

## 5. P6c 改动面：「改了什么」

今天的缺口是**非对称**：改动**之前**有预览，改动**之后**什么都没有 —— 用户只在确认那一刻看过一眼，之后屏幕上就再也没有它了。

| 元素 | 今天 | P6c |
| --- | --- | --- |
| 确认框预览 | 裸文本 `- / +` 前缀，无色 | `-` 红、`+` 绿、路径加粗、行数 `+3 −1` |
| 改完之后 | **什么都没有** | `⏺ Edit  src/parse.ts` → `⎿ +3 −1` |
| 每轮结束 | 没有 | `⎿ 本轮 3 次工具调用 · 改 2 个文件 · 1.2k tokens · 8.4s` |
| 退出时 | 没有 | 改了哪些文件、token 合计、转录路径（能 `--resume` 接上） |

**每轮摘要与 `/diff` 必须说同一件事** —— 两者都从那份 `changes` 表读（`cli/changes.ts`），不许各算一份。今天的教训是现成的：`cliPlugins` 顶部那段记的事故（`turn.step` 的应答者没进清单，模型说的话一个字都到不了终端，而三条命令全绿）就是"两条口径各写一遍"的后果。

`usageEstimated: true` 时（端点数是我们估的）摘要要**标出来**：`1.2k tokens（估）`。不标就是报假账，而 `turn.complete` 的注释里已经写明了这条口径。

### 5.1 判据

1. Edit 的预览与改后回显给的是同一份 diff（同一条断言跑两处）。
2. 每轮摘要的"改 N 个文件"与 `/diff` 的分块数一致。
3. `usageEstimated` 为真时摘要里出现"（估）"。

## 6. P6d 输入面

这一片碰的是 readline，风险与渲染不同，所以单独一片。

### 6.1 那块已经写进「已知限制」的欠账

README 里现在写着：**非 TTY 下 REPL 收不到输入** —— `echo '/diff' | deepcode` 无效。原因在 `main.ts` 与 `repl.ts` 之间：readline 建好了、主流程还没开始读，管道里的行在那段空窗里被读掉扔了。这一片修掉它，并且**先写一条会红的测试**再动手（判据见 6.4）。

### 6.2 粘贴多行：一个真存在的缺陷

readline 的 `question` 在**粘贴多行**时会把每一行都当成一次输入。粘贴 10 行代码进 REPL，会触发 10 次提交 —— 而其中任何一次都可能让模型去改文件。这不是"体验问题"，是**可能改错东西**。

修法：输入层不直接用 `question` 的逐行回调，改成收集 + **短去抖**（同一批到达的行合并成一次提交）。

**预登记的风险**：去抖窗口太短会把一次粘贴拆成多次提交，太长会把用户连着敲的两行合并。窗口定 **30ms**，并且**做不到可靠区分就退回"按行提交"**（今天的形状）—— 但那时要**明确写进帮助文本**，而不是让用户自己发现。

### 6.3 多行、历史、补全

| 项 | 做法 |
| --- | --- |
| 多行 | 行尾 `\` 续行（提示符换成 `… `）；`Ctrl-D` 结束输入 |
| 历史 | `~/.deepcode/history`，用户级 home、**0600**；上下键；`/clear` **不清**历史（清的是上下文） |
| 补全 | `/` 开头补命令名（名单来自既有的命令注册，不另抄一份）；`@` 开头补文件路径 |
| 修图 | 提示符 `> ` 与确认提示在视觉上分开（今天两者都是裸行） |

**`@` 路径补全的边界**：只做**当前工作目录内**的相对路径补全，不读用户主目录、不做跨盘符搜索。它扫的是路径，而路径**可以**指向任何地方 —— 但"用户可以自己敲出来"与"我们主动列给他"是两件事，后者要有理由。这条与"没有路径围栏"是两回事：围栏是**拦**，这里只是**不主动铺路**。

### 6.4 判据

1. `echo '/diff' | deepcode`（非 TTY）能跑出 `/diff` 的输出 —— 这条今天必须是红的，改完必须绿。
2. 粘贴 10 行只发生**一次**提交（脚本化 stdin 的字节流 + 一条断言数提交次数）。
3. 历史文件落盘在用户级 home，权限 0600（Windows 上退化为"不在项目目录里"这一条）。
4. 补全列表里出现的命令名，与命令注册表里的完全一致。

## 8. 风险与预登记的偏差

1. **终端能力探测不可靠**。`process.stdout.columns` 在 TTY 下也可能是 `undefined`（部分 Windows 终端）。退路：**只在 TTY 下**把它当 80；非 TTY 恒不折。
2. **Windows 上的光标上移**。`\u001b[<n>A` 在 Windows Terminal / ConPTY 下可用；SGR 已经在用（今天 palette 就是），说明现状可接受。**预登记**：若某个终端不支持上移，退路是"活动区只占一行"（今天的形状），擦除三步（`\r` + 每行 `\u001b[K` + 上移 n 行）都可单独降级。
3. **粘贴去抖的窗口**（§6.2）。30ms，做不到可靠区分就退回按行提交并写进帮助文本。
4. **流式 markdown 的边界**：未闭合围栏是流式途中的常态，按"渲染到底"处理；增量切在多字节字符中间也是常态，按 code unit 缓冲、只在 `\n` 处切。
5. **改 `render.ts` 会动到既有逐字节断言**（`test/cli.test.ts:82` 那一类）。那**正是**回归网，任何一条变红都要先问一句"是网该更新，还是我真的破坏了管道输出"。**预登记**：非 TTY 路径只允许零改动。
6. **活动区与 readline 抢终端**。确认提示、REPL 提示符都要在落笔前擦掉活动区 —— 今天 `beforeAsk` 是这条路唯一的显式接线点，多行活动区之后它必须仍然是**唯一**的那个口子。
7. **本片可能逼出一处内核改动**（例如活动区想要 hop 序号，而 `turn.complete` 里没有）。若真发生：**先记在这里**，说明为什么插件拿不到，再动 `src/core/`，并把出口标准 3 的断言改成"只允许这一处"。

## 10. 验收方式

沿用 P2/P4/P5：**按检查点批量做，任务级只跑 `pnpm typecheck`**，一片一个或数个检查点，检查点里跑全量 `pnpm test` + `pnpm lint`，并做**反向验证**（把断言改坏一次，确认它真的会红；任一条没红，修的是断言不是设计）。

每片还要各有一条**手工路径**（真终端里跑一遍，人眼看一次）—— 判据能证明"输出里有这几个字符"，证明不了"它看起来是对的"。这一条对界面工作尤其重要，也是本阶段唯一一条**不能**自动化的验收。

每片的出口都要能回答一个问题：**这条判据，我把它弄坏过没有？**
