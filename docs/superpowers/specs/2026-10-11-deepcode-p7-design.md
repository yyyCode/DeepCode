# DeepCode P7 记忆与上下文设计

> 对标 `claude-code-架构分析/11-memory-and-context.md`。复刻对象的事实、依据与版本锚点
> 都在那一份里，本文**不重述**，只写"我们缺什么、改什么、为什么、怎么验"。
>
> 一句话口径：**这一阶段不新增存储层，也不新增事件** —— 把已经有的三层（指令文件 /
> 转录 / 压缩）的账本、权威面与失败方向补齐。

---

## 1. 出口标准（可验证，四条）

1. **账本可见**：`/context` 报出这一轮上下文的构成 —— 系统提示逐节、会话消息、压缩阈值、
   自动压缩开关、上一次实测用量；并且**明说自己不知道模型窗口**，不报"还剩多少"。
2. **干预面可用**：`/compact <说明>` 的那段说明真的进了摘要那一轮（测试断言摘要请求里含它）。
3. **压缩后重装**：压缩边界上，被压掉的目录约定会**重新附上**（不是一次会话只附一次就完事）。
4. **失败方向收口**：摘要连续失败 3 次、或连续压缩 3 次后上下文立刻又满 → **停手**，
   报一条可操作的错，而不是每轮再试一次并刷屏。

任务级验收只跑 `pnpm typecheck`；测试按检查点批量做（用户长期指令：一次校验多个任务）。

## 2. 与复刻对象的差异

复刻对象把"记忆"拆成六层寿命不同的存储 + 一个接缝（`11-memory-and-context.md:12-21`）。
逐层对我们：

| 层 | 复刻对象 | 我们**已有** | 差距 → 本阶段怎么办 |
| --- | --- | --- | --- |
| **L0 预算账本** | `SessionContextBreakdown`（`/context` 的数据源）、有效窗口 = 模型窗口 − 输出预留 − buffer | 只有每轮一行 `1.2k tokens`（`cli/tally.ts`）；阈值是 `compact.atTokens` 默认 10 万，**且注释里自己写了"这个默认值是猜的"** | 差距在**可见性**，不在算法。→ §3.1 `/context` |
| **L1 常驻注入** | 每轮重新求值（答案会被会话缓存，配置变更即失效），压缩与 `/clear` 天然重置注入状态 | `prompt.section` 只在**启动时**求值一次，之后整场会话复用同一个字符串（`cli/main.ts:396-404`） | 真差距。→ §3.2 每轮重算 |
| **L2 会话转录** | append-only JSONL，`--resume` | 已有，含分桶/真实 cwd/0600/坏行跳过（`cli/transcript.ts`） | 只差一处游标失效 → §3.6 |
| **L3 压缩** | `SessionCompactInput{trigger, agentId, instructions, messages}`、三重断电器、摘要即一条消息 | 已有"摘要即一条消息"这条最关键的设计（`cli/compact.ts:124-128`）；但 `instructions` 是写死的常量、没有断电器、没有抖动判定 | → §3.3 干预面、§3.5 断电器 |
| **L4 持久记忆** | Markdown + 硬上限 + 显式报错 + 注入面消毒 | 五个来源都有了（`mods/agents-md/instructions.ts`），**没有"记忆写入"这条线也没有上限** | 不追（见 §4）：我们的 `AGENTS.md` 是人写的，没有 auto-memory 这种引擎写入者 |
| **L5 恢复与回滚** | 文件版本备份 + `/rewind` | 只有 `/diff`（本会话改动表，内存） | 不追（见 §4）：属于新的存储面 |
| 接缝 | `prompt.context`（装填） / `session.compact`（卸载） | 两个都在，且都是事件 | 不在两个事件之间加新的路 |

复刻对象给复刻者的 14 条启示里，**我们真正要抄的是 4 条**：账本先于压缩（启示 1）、
压缩是带类型的操作（启示 2）、压缩后重装文件而不是把文件压进摘要（启示 8）、
三重断电器（启示 7）。其余 10 条逐条在 §4 里有"不追"的理由 —— 别把它们当成待办。

## 3. 逐项设计

### 3.1 账本可见：`/context`

**是什么**：一条新命令，把"这一轮到底往窗口里塞了什么"打成几行。

```
上下文账本（都是估的，除了"上次实测"）
  系统提示   12 345 token —— base 1 234 · instructions 9 876 · offer 1 235
  会话消息   34 567 token（12 条）
  合计       46 912 token
  阈值      100 000 token · 自动压缩 关 · 保留最近 6 轮
  上次实测   41 002 token（端点报的）
```

**为什么**：压缩这件事今天对一个用户是完全黑箱 —— 阈值藏在设置文件里、用量只在每轮
那一行流水里、`/compact` 之后发生了什么都不出声（只说一句"已压缩"）。复刻对象把账本
做成一等数据（`SessionContextBreakdown`）的理由是"三次事故全部源于账本算错"，而对我们
更直接的理由是：**阈值这个数我们自己都标着"猜的"，那就更该让它出现在屏幕上**。

**落点**：

- 新增 `src/cli/context-view.ts`：纯函数，`(input) => readonly string[]`，不碰引擎、不碰渲染。
- `src/cli/commands.ts` 加 `/context`（与 `/compact` 同一族：要外设，所以住 `cli/`）。
- `compact.ts` 的 `Compactor` 补一个 `usage()`：把最近一次 `note()` 收到的东西原样交出来 ——
  `/context` 的"上次实测"就是它，**没有第二本账**。

**口径三条（都不许含糊）**：

1. **不报"还剩多少"**。我们**没有模型注册表**，不知道模型窗口是多少；有效窗口 = 窗口 −
   输出预留 − buffer 这条式子，我们连第一项都没有。所以账本只报"我们知道的"：阈值是我们
   唯一一个自己定的数，就把它连同它的出身（`compact.atTokens`，默认值标注为猜的）一起报。
2. **估就是估**。系统提示与消息都是 `estimateTokens(chars)`（`core/loop.ts:227`，按 4 字符
   1 token 粗估，中英混排会失真）。只有端点报了 usage 的那一行不标"（估）"，其余全标。
3. **一节的账要能对上总量**：逐节之和 = 系统提示那一行，系统提示 + 消息 = 合计。
   对不上说明有东西没被算进去 —— 那是账本算错，不是显示问题。

**判据**：造一个已知大小的 system prompt 与消息数组，断言 `/context` 的行里逐节之和等于
合计；再断言它**不含**任何形如"还剩 / 剩余窗口"的字样（这条钉的是"不假装知道窗口"）。

### 3.2 每轮重算注入面

**是什么**：`prompt.section` 与 `agent.offer` 从"启动时算一次"改成"每轮算一次"。

**为什么**（两条，第二条才是这次的重点）：

1. 会话中改 `AGENTS.md` 之后当场生效，不必重启 —— 复刻对象的 `prompt.context` 属于
   "答案被会话缓存、配置变更即失效"的那六个事件，效果一样。
2. **压缩之后注入面必须重新求值**。今天指令文件是启动时读一次拼好的，压缩把上下文改短
   之后那份字符串不会重建 —— 单看指令文件还好（它还在 system prompt 里、没被压掉），
   但"每轮重算"是 §3.4 那条能成立的前提：既然约定是可重算的，压缩后重装就只是"重算一次"，
   而不是一条特例。

**落点**：新增 `src/cli/system-prompt.ts`：

```ts
export type PromptPiece = { readonly name: string; readonly text: string };
export type BuiltPrompt = { readonly text: string; readonly pieces: readonly PromptPiece[] };
export type PromptBuilder = {
  build(): Promise<BuiltPrompt>;      // 每轮重算
  last(): BuiltPrompt | undefined;    // /context 用：最近算过的那一份
};

export function createPromptBuilder(deps: { base: string; dispatch: DispatchFn }): PromptBuilder;
```

`main.ts` 用它替掉那三行拼接；`repl.ts` 的 `systemPrompt: string` 改成
`systemPrompt: () => Promise<string>`（**只改这一个字段**，`core/loop.ts` 的 `runTurn`
仍然收字符串，一层不多动）。`/context` 通过 `builder.last()` 拿到分节明细，不另算一遍。

**代价（写进代码注释）**：每轮多 3 次文件读（最多），以及系统提示的字节**可能在会话中途
变化**。我们不主动管 prompt cache（端点侧隐式），所以这条只影响隐式命中；但语义上它是
真变化，得写清楚 —— 复刻对象为此专门冻结过"记忆文件年龄注记"（`2.1.275`），我们没到
那一步，记在这里备查。

### 3.3 压缩的干预面：`/compact <说明>`

**是什么**：`/compact` 收一段可选说明，拼进摘要那一轮的提示。

**为什么**：复刻对象把 `session.compact.instructions` 叫作"最被低估的扩展点"。长会话里
用户最需要的是"压掉前面，但保住这几件事"—— 而我们的摘要提示是写死的常量
（`compact.ts:14-19`），用户一个字都插不进去。这是**最便宜的一条干预面**：不加事件、
不加设置项，只多传一个参数。

**落点**：

- `Compactor.run(trigger, instructions?)`；`summarize()` 里把说明拼成
  `SUMMARIZE_PROMPT + "\n\n用户额外要求（优先满足）：\n" + instructions`。
- `cli/commands.ts` 的 `compact?: (instructions?: string) => Promise<void>`；`/compact` 的
  args 用空格 join（`input.ts:135` 就是这么切的，中文说明会被切成多个 arg）。
- `/help` 的 describe 改一句，把"可以带说明"说出来。

**判据**：给一个假的 provider，断言它收到的摘要请求里含那段说明；不传说明时，
摘要请求**逐字节**等于改动前的那一份（这一条防的是"顺手把提示词也改了"）。

### 3.4 压缩后重装：目录约定

**是什么**：`mods/agents-md/nested.ts` 订阅 `session.compact`，把"一个文件只附一次"的
去重表清空。

**为什么**：这是"记忆越压越糊"的第一个实例。惰性附加的去重表以**插件实例**为界，
而插件实例活过一次压缩；压缩把附在 `Read` 结果后面的约定从上下文里拿掉了，去重表却
仍记着"这个文件附过了" —— 于是**它永远不会再被附上**，模型丢了约定还不知道自己丢了。

复刻对象的正确姿势写在 `InstructionsLoaded.load_reason` 里：有 `'compact'` 这个取值 ——
**压缩边界上重新装载文件，而不是把文件压进摘要**。对话有损，文件无损。

**落点**：`nested.ts` 里加一条 `on('session.compact', ...)`，`attached.clear()` 后
`return next(e)`（与 `cli/activity.ts:183`、`mods/telemetry/index.ts:114` 同一写法）；
`uses` 里补上 `'session.compact'`。

**判据**：同一份目录约定，压缩前附过一次（第二次读不再附）；压缩之后再读同一个文件，
**重新附上**。反向断言同时要有：不压缩时它**不会**重复附（否则就是复制粘贴刷上下文，
那正是复刻对象 `2.1.89` 修过的 bug）。

### 3.5 断电器

**是什么**：两条闸，都在 `cli/compact.ts` 里，数取 3（照复刻对象的断电器抄的，
**不是我们测出来的**，注释里如实写）。

| 闸 | 触发 | 行为 |
| --- | --- | --- |
| 连续摘要失败 | `run()` 失败（调用失败 / 空摘要 / 摘要没更短）累计 3 次 | **自动压缩停手**，报一条可操作的错 |
| 抖动 | 连续 3 次压缩成功之后，下一轮实测用量**仍然 ≥ 阈值** | **自动压缩停手**，报可操作的错 |

- **只掐自动**。手动 `/compact` 永远给你一次机会，并且把两个计数与"已停手"一起清掉 ——
  用户手敲的那一下是他的判断，不是我们的重试。
- 某轮落在阈值之下 → 两个计数归零（"压缩真的奏效了"）。
- 停手的理由**说一次**就不再刷屏（现状是每轮都可能重复一句"压缩没做成"，那正是要修的形状）。
- 报错要**可操作**：说清停的是什么（自动压缩）、怎么恢复（输入 `/compact` 手动再试一次 /
  把 `compact.auto` 关掉 / 把 `compact.atTokens` 调大）。

**为什么**：复刻对象的 `2.1.76` / `2.1.89` / `2.1.284` 三条连起来讲的是同一件事 ——
压缩会**失败**、会**抖动**、会**压完还满**，而引擎的反应不能是"那就再试一次"。
我们今天的形状恰好是后者：`auto: true` 时每轮 `afterTurn` 都可能再压一次，
失败只是 `warn` 一句，一句一句刷下去。

**判据**：假 provider 让它连续三次返回空摘要 → 断言第四次 `afterTurn` **不再调用**它，
且屏幕上那句只说了一次；再造一个"压完仍超阈值"的序列 → 断言 3 次后停手。

### 3.6 修一处静默失效：`/clear` 之后的落盘游标

**是什么**：`/clear` 在清空 `messages` 之后跟着 `persist.reseed(0)`。

**为什么**：落盘器内部记着"已经写到第几条"（`transcript.ts:113-148`），压缩把它改短之后
必须 `reseed`，这条今天只有 `compact.ts:144` 一处调用。`/clear` 也把数组改短（到 0），
却没有 reseed，后果是**新对话前 N 条消息静默不落盘**，等数组再长过旧游标才从
`slice(N)` 继续写 —— 盘上变成"旧对话 + 新对话的一段尾巴"，`--resume` 接回来缺开头，
而且一声不吭。

这与 `transcript.ts:105` 那句"这是唯一一处会静默损坏数据的地方"直接冲突，也是
`/clear` 那句提示（"磁盘上的转录保留"）给人的预期之外的东西：保留旧的是对的，
新的半截丢了没人说。

**落点**：`cli/commands.ts` 的 `/clear` 分支里，清空之后调 `deps.persist.reseed(0)`。
要给它一个落盘器的口子（与 `compact` 那个延迟取的回调同一写法）。

**判据**：落盘到 3 条 → 清空 → 再走一轮（2 条）→ 断言盘上是**旧的 3 条 + 新的 2 条**，
顺序不错、开头不缺。

**这条要进 CHANGELOG 的偏差节**（如实记：这是修一处静默失效，不是新功能）。

## 4. 明确不做（YAGNI，逐条给理由）

| 复刻对象有 | 启示 # | 我们不做的理由 |
| --- | --- | --- |
| 语义检索 / embedding / 向量库 | — | 复刻对象自己也没做（`11-...:55`）。文件全量注入、行为可预测，这条我们要保持。 |
| auto-memory（引擎自己写记忆文件）、`MEMORY.md` 索引与 25KB/200 行上限 | 10、11 | 我们的 `AGENTS.md` 是**人写的**，没有引擎写入者，也就没有"记忆膨胀"这个问题可治。真要做，它是一整条新存储线 + 一个新的写入面（还是不可信输入面），不塞进这一阶段。 |
| 记忆文件的注入面消毒（中和不可见字符与"模仿自家标记"的标签） | 11 | 同理：我们的注入内容是人写的，且已在 `Description` 里写明"记忆是文件"。等有了引擎写入者，这条是**必须**跟着做的第一件事 —— 记在这里，不是忘了。 |
| `/rewind` + 文件版本备份（`cleanupPeriodDays`） | 8、12 | 新存储面（文件版本 + 清理策略），与"记忆"相邻但不是同一件事。 |
| prompt cache 稳定性清单（日期移出提示、注记冻结、TTL 可配） | 5、9 | 我们不主动管缓存，命中由端点侧隐式决定。要抄的是"任何改动请求前缀的东西都要问会不会打断缓存"这条**评审习惯**，不是这套机制。 |
| 投机压缩 `precompute` | 2 | 我们一次请求只有一轮摘要调用，提前算没有落点。 |
| 工具结果外置落盘（50K 字符 → 引用） | 13 | 我们有**截断**（`Read` 2000 行 / `Bash` 40 000 字符 / `Grep` 200 条）。外置要新增一个用户级存储面（还得守 0600 那条规矩）并让模型学会"去哪读全文"，收益不到那一步。 |
| 每轮注入"剩余预算"提示 | 14 | 与 §3.1 冲突：我们说不清"剩下多少"，那就不该往上下文里塞一个自己都不信的数。 |
| `PreCompact` 可否决 / `session.summarize` 改写摘要要求（hook 面） | 5 | 本阶段只做**用户面**那半（§3.3）。hook 面要新开一个缝事件或把 `session.compact` 从纯通知改成缝（会波及 activity 与 telemetry 两个订阅者），等有真实需求再做。 |
| `PostCompact` 读摘要全文做审计 | 4 | 我们的 `session.compact` 派在**改之前**（`tokensBefore` 这个名字只在改之前说得通），所以今天没有任何地方能观察到压缩的**结果**。真要做审计，落点是把摘要正文交给 telemetry —— 那是新事件，不是这一阶段。 |

## 5. 偏差与代价（如实写）

1. **账本不知道窗口**。只报阈值与构成，不报"还剩多少"。这是**如实**，不是没做完 ——
   我们没有模型注册表，凭模型名猜窗口就是编数字。
2. **每轮重算会让系统提示字节在会话中变化**。§3.2 的代价，已写在代码注释里。
3. **断电器那三个 3 是抄来的数**。不是我们测出来的经验值，注释里标明出处。
4. **`/clear` 的游标修复不能救已经写坏的转录**。它只保证之后的会话不错位。
5. **`/context` 的 token 数是估的**。`estimateTokens` 按 4 字符 1 token，中英混排失真；
   只有端点报了 usage 的那一行不是估的，所以那一行**单独列**，不混进构成里。

## 6. 任务分解与验收

| # | 任务 | 落点 | 验收 |
| --- | --- | --- | --- |
| 1 | `/context` 账本 | 新增 `cli/context-view.ts`、`commands.ts`、`compact.ts` 补 `usage()` | 单测：逐节之和 = 合计；不含"还剩"字样 |
| 2 | 每轮重算注入面 | 新增 `cli/system-prompt.ts`、`main.ts`、`repl.ts` 一个字段 | 断言两次 `build()` 之间改文件会反映出来 |
| 3 | `/compact <说明>` | `compact.ts`、`commands.ts` | 断言摘要请求含说明；不传时逐字节等于旧提示 |
| 4 | 压缩后重装约定 | `mods/agents-md/nested.ts` | 压缩后重新附上；不压缩时不重复附 |
| 5 | 断电器 | `compact.ts` | 连续 3 次失败 → 停手且只说一次；抖动 3 次 → 停手 |
| 6 | `/clear` 落盘游标 | `cli/commands.ts` | 清空后新对话照常落盘、旧的保留 |

**检查点**（批量做，不逐任务卡）：
