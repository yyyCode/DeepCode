# DeepCode P3（扩展面）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让一个**掉进目录**的插件能扩展出新的用户能力 —— 加一个新工具、挂一条 classic hook 拦住工具调用 —— 同时不让它放宽任何一行权限。

**Architecture:** 三块拼起来。① `src/contract/` 两份纯逻辑：`plugin-manifest.ts`（清单与钩子的校验，`plugin validate` 与加载器共用同一份实现）与 `classic.ts`（33 个 classic 事件名 + 桥接白名单）。② `src/cli/` 三份装载件：`plugin-dir.ts`（发现与 import）、`classic-hooks.ts`（把钩子组翻译成以**该插件自己的名字**注册的 hook）、`hook-run.ts`（唯一的 spawn 点）。③ `src/core/` 里第三方插件的 `on` 被包装过：剥掉 `allow` 判定、按 `uses` 查越界、拒绝往 `engine.create` 挂 hook，座位强制成 `append`。准入闸门 `plugin.register` 由第一方插件 `plugin-guard` 应答（坐 `prepend`），它的判定依据是五层 settings 合并出来的 `plugins.deny`。

**Tech Stack:** TypeScript（ESM，`strict` + `noUncheckedIndexedAccess` + `verbatimModuleSyntax`）、Node ≥ 20、pnpm、vitest 2.1.9、tsx。**零运行时依赖**，这一条不允许破 —— 插件系统一个第三方包都不许引。

**设计文档:** [`docs/superpowers/specs/2026-10-11-deepcode-p3-design.md`](../specs/2026-10-11-deepcode-p3-design.md)

**前序:** [`P2 计划`](2026-10-11-deepcode-p2.md)（同体例先例，含执行记录与偏差清单）

## 边界规则

`scripts/check-boundaries.mjs` 的硬约束，P3 新增的文件必须落在里面：

| 目录 | 允许 import |
|---|---|
| `src/contract/` | **只有 node 内置类型**，不能 import 任何 `src/` 里的东西 |
| `src/core/` | `contract` |
| `src/providers/` | `contract` |
| `src/builtins/` | `contract` |
| `src/cli/` | `contract`、`core`、`providers`、`builtins` |

三条推论，直接决定了 P3 的文件放哪：

- **校验必须是纯逻辑 → 住 `contract/plugin-manifest.ts`。** `plugin validate` 与加载器要共用同一份实现（设计 §1），而 `cli/` 能 import `contract/`、`builtins/` 也能，反过来不行。放进 `cli/` 就只有 cli 能用得上。
- **探目录、读文件、起子进程 → 住 `cli/`。** 它们要 `node:fs`/`node:child_process`，而 `builtins/` 只有 `contract` 的 import 权限（`builtins/tools/bash.ts` 用的是注入进来的 `$.process`，自己不开进程 —— 这就是那条边界的落法）。
- **`plugin-guard` 要答 `plugin.register` → 住 `builtins/`。** 它是第一方插件，只接收解析好的 deny 名单与第一方名字清单（`createPluginGuardPlugin({ deny, firstParty })`），与 `createPermissionsPlugin({ rules })` 是同一手法。

```ts
/**
 * Classic hooks 的契约：事件名、`hooks.json` 的形状、以及我们**真正桥接**的那三个事件。
 *
 * 三样东西放一个文件，是因为它们必须一起改：加一个桥接事件 = 白名单里加一条 + 映射表里加一条。
 * 白名单有 33 个而映射只有 3 个，这个不对称本身就是信息（设计 §5.1）—— 它是"参考实现有 33 个事件、
 * 我们只找到 3 个着陆点"的如实呈现，不是没做完。
 */

/**
 * classic hooks 的 33 个事件名。
 *
 * ⚠️ **这不是 33 个引擎事件。** 引擎事件目录在 `events.ts`（39 个声明 / 12 个实现）。
 * classic 事件是**另一份目录**：它们从 `hooks.json` 里读进来，落到我们已有的钩子点上。
 * 为它们各造一个引擎事件是白造 —— 没人会 dispatch 一个叫 `classic.PreToolUse` 的东西。
 * 见设计 §11 偏差 1。
 */
export const CLASSIC_EVENTS = [
  'PreToolUse',
  'PostToolUse',
  'PostToolUseFailure',
  'PostToolBatch',
  'PermissionRequest',
  'PermissionDenied',
  'Notification',
  'UserPromptSubmit',
  'UserPromptExpansion',
  'SessionStart',
  'SessionEnd',
  'Stop',
  'StopFailure',
  'SubagentStart',
  'SubagentStop',
  'PreCompact',
  'PostCompact',
  'PreModelSwitch',
  'PostModelSwitch',
  'Setup',
  'TeammateIdle',
  'TaskCreated',
  'TaskCompleted',
  'Elicitation',
  'ElicitationResult',
  'ConfigChange',
  'InstructionsLoaded',
  'WorktreeCreate',
  'WorktreeRemove',
  'CwdChanged',
  'FileChanged',
  'DirectoryAdded',
  'MessageDisplay',
] as const;

export type ClassicEvent = (typeof CLASSIC_EVENTS)[number];

const CLASSIC_SET: ReadonlySet<string> = new Set(CLASSIC_EVENTS);

export function isClassicEvent(name: string): name is ClassicEvent {
  return CLASSIC_SET.has(name);
}

/**
 * 桥接表：classic 事件 → 我们已有的钩子点。
 *
 * 只有三个，因为**只有这三个已经有着陆点**。`PostToolUse` 要一个 `tool.result` 事件、
 * `Stop` 与 `UserPromptSubmit` 要一条能携带文本的通道 —— 都得动事件目录或 prompt 组装面，
 * 排在 P4（设计 §11 偏差 2）。
 */
export const BRIDGED_EVENTS = {
  PreToolUse: 'tool.check',
  SessionStart: 'session.start',
  SessionEnd: 'session.end',
} as const;

export type BridgedEvent = keyof typeof BRIDGED_EVENTS;

const BRIDGED_SET: ReadonlySet<string> = new Set(Object.keys(BRIDGED_EVENTS));

export function isBridged(name: string): name is BridgedEvent {
  return BRIDGED_SET.has(name);
}

/** `hooks.json` 里的一个钩子定义。未知字段原样留着 —— 校验器要点名"未识别的字段"。 */
export type HookDef = {
  readonly type?: unknown;
  readonly command?: unknown;
  readonly timeout?: unknown;
  readonly [key: string]: unknown;
};

/** 一个 matcher 组：一个 matcher + 一组钩子（组内串行）。 */
export type HookGroup = {
  readonly matcher?: unknown;
  readonly hooks?: unknown;
  readonly [key: string]: unknown;
};

/** 一份 `hooks.json` 的正文：事件名 → matcher 组数组。 */
export type HookConfig = Readonly<Record<string, unknown>>;

/** 归一之后的一个钩子：命令原文 + 毫秒超时。 */
export type ResolvedHookDef = {
  readonly command: string;
  readonly timeoutMs: number;
};

/**
 * 归一之后的一个 matcher 组。
 *
 * `tools === undefined` 表示"对所有工具生效"（matcher 是 `*` 或没写）。
 * 正则形态的组**不会**出现在这里 —— 它在校验期就被跳过并警告了（设计 §5.3）。
 */
export type ResolvedHookGroup = {
  readonly event: BridgedEvent;
  readonly tools: readonly string[] | undefined;
  readonly hooks: readonly ResolvedHookDef[];
};

/**
 * 钩子超时的默认值与上限（秒）。
 *
 * 参考实现的默认值是 60 秒，那是给"可能做一次 LLM 调用"的钩子留的余量。
 * 我们桥的三个事件里，`PreToolUse` 是**同步挡在每一次工具调用前面**的 ——
 * 一个手滑的钩子把 CLI 冻住一分钟是用户敌意。收紧到 10 秒，见设计 §11 偏差 4。
 */
export const DEFAULT_HOOK_TIMEOUT_S = 10;
export const MAX_HOOK_TIMEOUT_S = 300;

/**
 * classic matcher 的三档：`*`（全部）、精确名或 `A|B`（拆开）、以及正则形态（不支持）。
 *
 * 判断用**字符集**而不是"试着编译成正则"：`Delete` 也能编译成正则，可它是个工具名。
 * 允许的字符集是 `[A-Za-z0-9_|]`，这之外的任何字符（`.` `*` `^` `(` …）一律当正则形态。
 * `*` 单独先判掉 —— 它是最常见的那个"全部"，且 `*` 本身也是正则元字符。
 *
 * 判成 `'regex'` 之后是**跳过**这一整组，不是"当精确名比对"：一条本意只覆盖
 * `mcp__.*__delete.*` 的规则若被放大到所有工具，那是**放宽**，方向不对的降级不做。
 */
export function parseMatcher(matcher: string): '*' | readonly string[] | 'regex' {
  const trimmed = matcher.trim();
  if (trimmed === '*') return '*';
  // 先把 `|` 两侧的空白抹平，再判字符集：`Write | Edit` 是列表，而 `a b` 不是 ——
  // 后者中间那个空格不挨着任何分隔符，于是它留在字符串里被字符集挡下，判成正则形态。
  const collapsed = trimmed.replace(/\s*\|\s*/g, '|');
  if (!/^[A-Za-z0-9_|]+$/.test(collapsed)) return 'regex';
  const names = collapsed.split('|').filter((name) => name !== '');
  // 空数组会被下游读成"只对零个工具生效"—— 那是个安静的失效。判成 regex 至少会吼一声。
  return names.length === 0 ? 'regex' : names;
}
```

```ts
import { describe, expect, it } from 'vitest';
import {
  isSafeRelativePath,
  validatePlugin,
  type PluginReader,
  type Problem,
} from '../src/contract/plugin-manifest';

/**
 * 一张 相对路径 → 内容 的表，外加一张"存在的路径"的集合。
 * 没列在 files 里的路径 = 读不到；只有列在 dirs 里的才 exists。
 */
function reader(files: Record<string, string>, dirs: readonly string[] = []): PluginReader {
  return {
    read: async (relative) => files[relative],
    exists: async (relative) => relative in files || dirs.includes(relative),
  };
}

const GOOD = JSON.stringify({
  name: 'secret-guard',
  version: '0.1.0',
  description: '拦住把密钥写进仓库',
  uses: ['tool.check'],
});

const HOOKS = JSON.stringify({
  hooks: {
    PreToolUse: [{ matcher: 'Write|Edit', hooks: [{ type: 'command', command: 'node guard.mjs', timeout: 5 }] }],
  },
});

function codes(problems: readonly Problem[], level: 'error' | 'warn'): string[] {
  return problems.filter((p) => p.level === level).map((p) => p.code);
}

async function run(files: Record<string, string>, dirs: readonly string[] = []) {
  return validatePlugin('plugins/x', reader(files, dirs));
}

describe('路径的四条硬规则', () => {
  it.each(['./hooks/hooks.json', './main.mjs', './a/b/c.md'])('放行 %j', (value) => {
    expect(isSafeRelativePath(value)).toBe(true);
  });

  it.each([
    'hooks/hooks.json', // 少了 ./
    '/etc/passwd', // 绝对路径
    '../shared/hooks.json', // 逃出插件目录
    './a/../../b', // 同样逃出去，只是绕了一下

    './a\\..\\..\\b',

    expect(isSafeRelativePath(value)).toBe(false);
```

```ts
  parseMatcher,
  type ResolvedHookDef,
  type ResolvedHookGroup,

/**
 * 插件清单与 `hooks.json` 的校验。
 *
 * **零 IO：** 所有读取都从 `PluginReader` 注入，于是这份判定能在没有文件系统的地方跑，
 * 也能被 `plugin validate` 与加载器**共用同一份实现** —— 出口标准二要求
 * "validate 能拦住坏清单"，而拦住它的必须是加载器也认的那条规则，不是另写一遍。
 *
 * 两级：E 是错误（装不上），W 是警告（装得上，但照这么写会不work 或本版本不认）。
 * 两者的区别必须一眼看得出来。
 */

export type Problem = {
  readonly level: 'error' | 'warn';
  /** 规则编号（`E3` / `W7`）。测试与输出都按它点名。 */
  readonly code: string;
  readonly message: string;
};

export type PluginManifest = {
  readonly name: string;
  /** 没写就是 `0.0.0`。 */
  readonly version: string;
  readonly description: string | undefined;
  readonly homepage: string | undefined;
  readonly author: string | undefined;
  /** 声明的扩展面。没写就是空数组 = 什么都不许注册。 */
  readonly uses: readonly string[];
  /** 声明过的路径字段 → 值。没声明的字段不在这里。 */
  readonly paths: Readonly<Record<string, readonly string[]>>;
};

/**
 * 相对插件目录的读取面。
 *
 * 两个方法都要，因为目录不可读成文本，而声明的路径既可能是文件也可能是目录。
 * 实现只在拿到**通过 `isSafeRelativePath` 的路径**之后才会被调用 —— 逃逸由校验器先拦下。
 */
export type PluginReader = {
  read(relative: string): Promise<string | undefined>;
  exists(relative: string): Promise<boolean>;
};

export type Validated = {
  readonly problems: readonly Problem[];
  /** 有没有 E 级问题。false = 装不上。 */
  readonly ok: boolean;
  /** 全绿时的归一清单。有 E 时是 undefined。 */
  readonly manifest: PluginManifest | undefined;
  /** 入口模块的相对路径。没声明就按顺序探测，都没有是 undefined。 */
  readonly entry: string | undefined;
  /** 归一后的钩子组：只留桥接事件，matcher 已展开，timeout 已给默认值。 */
  readonly hooks: readonly ResolvedHookGroup[];
};

const NAME_RE = /^[a-z][a-z0-9]*(-[a-z0-9]+)*$/;
const VERSION_RE = /^\d+\.\d+\.\d+(?:[-+][0-9A-Za-z.-]+)?$/;
const MAX_NAME_LENGTH = 64;

/** `commands`/`agents`/`skills`/`mcpServers`：本版本只校验存在性，不加载（设计 §11 偏差 1）。 */
const NOT_LOADED_FIELDS = ['commands', 'agents', 'skills', 'mcpServers'] as const;

/** 目录里的约定部件 → 对应的清单字段。W8 用它点名。 */
const CONVENTION_DIRS = [
  ['./commands', 'commands'],
  ['./agents', 'agents'],
  ['./skills', 'skills'],
  ['./.mcp.json', 'mcpServers'],
] as const;

export const PATH_FIELDS = ['entry', 'hooks', 'commands', 'agents', 'skills', 'mcpServers'] as const;
export type PathField = (typeof PATH_FIELDS)[number];

const KNOWN_FIELDS: ReadonlySet<string> = new Set([
  'name',
  'version',
  'description',
  'author',
  'homepage',
  'uses',
  ...PATH_FIELDS,
]);

/** 入口模块的探测顺序。与 Node 的 ESM 解析习惯一致：.mjs 最先。 */
const DEFAULT_ENTRIES = ['./main.mjs', './main.js', './main.ts'] as const;
const DEFAULT_HOOKS_PATH = './hooks/hooks.json';

/**
 * 相对路径的四条硬规则：以 `./` 开头、不含 `..`、不含反斜杠、非空。
 *
 * `..` 是唯一能让清单逃出插件目录的写法，这条是本文件最要紧的校验。
 * 反斜杠一起禁，因为 Windows 上 `a\..\..\b` 会被 path 归一成逃逸路径 ——
 * 光禁 `..` 而放行反斜杠，等于在另一个平台上把这道闸门自己拆了。
 */
export function isSafeRelativePath(value: string): boolean {
  return value.startsWith('./') && !value.includes('..') && !value.includes('\\');
}

function message(error: unknown): string {
  return error instanceof Error ? error.message : String(error);
}

export async function validatePlugin(label: string, read: PluginReader): Promise<Validated> {
  const problems: Problem[] = [];
  const err = (code: string, text: string): void => {
    problems.push({ level: 'error', code, message: text });
  };
  const warn = (code: string, text: string): void => {
    problems.push({ level: 'warn', code, message: text });
  };

  const giveUp = (): Validated => ({
    problems,
    ok: false,
    manifest: undefined,
    entry: undefined,
    hooks: [],
  });

  // ── E2 清单读得到、是好 JSON、顶层是对象 ──
  let text: string | undefined;
  try {
    text = await read.read('plugin.json');
  } catch (error) {
    err('E2', `${label} 里的 plugin.json 读不了：${message(error)}`);
    return giveUp();
  }
  if (text === undefined) {
    err('E2', `${label} 里没有 plugin.json`);
    return giveUp();
  }

  let raw: unknown;
  try {
    raw = JSON.parse(text);
  } catch (error) {
    err('E2', `plugin.json 不是合法 JSON：${message(error)}`);
    return giveUp();
  }
  if (typeof raw !== 'object' || raw === null || Array.isArray(raw)) {
    err('E2', 'plugin.json 顶层不是一个对象');
    return giveUp();
  }
  const record = raw as Record<string, unknown>;

  // ── E3 name ──
  const rawName = record.name;
  let name: string | undefined;
  if (typeof rawName !== 'string') {
    err('E3', '缺少 name（必填，字符串）');
  } else if (rawName.length > MAX_NAME_LENGTH) {
    err('E3', `name 有 ${rawName.length} 个字符，上限 ${MAX_NAME_LENGTH}`);
  } else if (!NAME_RE.test(rawName)) {
    err('E3', `name ${JSON.stringify(rawName)} 不是 kebab-case（要求 ${String(NAME_RE)}）`);
  } else {
    name = rawName;
  }

  // ── E4 version ──
  const rawVersion = record.version;
  if (rawVersion !== undefined && (typeof rawVersion !== 'string' || !VERSION_RE.test(rawVersion))) {
    err('E4', `version ${JSON.stringify(rawVersion)} 不是 semver`);
  }

  // ── W1 未知顶层字段 ──
  // 只警告不致命：清单比引擎活得久，一个只在 P4 有意义的字段不该让插件装不上。
  const unknown = Object.keys(record).filter((key) => !KNOWN_FIELDS.has(key));
  if (unknown.length > 0) {
    warn('W1', `未识别的清单字段：${unknown.join('、')}（本版本忽略）`);
  }

  // ── E5 展示字段 ──
  for (const field of ['description', 'homepage'] as const) {
    const value = record[field];
    if (value !== undefined && typeof value !== 'string') err('E5', `${field} 必须是字符串`);
  }
  const rawAuthor = record.author;
  if (
    rawAuthor !== undefined &&
    typeof rawAuthor !== 'string' &&
    (typeof rawAuthor !== 'object' || rawAuthor === null || Array.isArray(rawAuthor))
  ) {
    err('E5', 'author 必须是字符串或对象');
  }

  // ── E6 + E8 路径字段 ──
  const paths: Record<string, readonly string[]> = {};
  for (const field of PATH_FIELDS) {
    const value = record[field];
    if (value === undefined) continue;

    const values = typeof value === 'string' ? [value] : Array.isArray(value) ? value : undefined;
    if (values === undefined || values.some((item) => typeof item !== 'string')) {
      err('E6', `${field} 必须是字符串或字符串数组`);
      continue;
    }
    const list = values as string[];

    const unsafe = list.find((item) => !isSafeRelativePath(item));
    if (unsafe !== undefined) {
      err(
        'E6',
        `${field} 的路径必须是相对的、以 ./ 开头、不含 .. 与反斜杠，实际是 ${JSON.stringify(unsafe)}`,
      );
      continue;
    }

    for (const item of list) {
      if (!(await read.exists(item))) err('E8', `${field} 指向的 ${item} 不存在`);
    }
    paths[field] = list;
  }

  // ── E7 uses ──
  const rawUses = record.uses;
  let uses: readonly string[] = [];
  if (rawUses !== undefined) {
    if (!Array.isArray(rawUses) || rawUses.some((item) => typeof item !== 'string')) {
      err('E7', 'uses 必须是字符串数组');
    } else {
      uses = rawUses as string[];
    }
  }

  // ── W8 约定目录：没声明但有，或声明了但本版本不加载 ──
  for (const [dir, field] of CONVENTION_DIRS) {
    if (paths[field] === undefined && (await read.exists(dir))) {
      warn('W8', `有 ${dir}，但清单没在 ${field} 里声明它 —— 本版本不加载`);
    }
  }
  for (const field of NOT_LOADED_FIELDS) {
    if (paths[field] !== undefined) {
      warn('W8', `${field} 在本版本不加载（P4 的组件面），这一项只做了存在性校验`);
    }
  }

  // ── 入口模块：声明优先，否则按固定顺序探测 ──
  let entry = paths.entry?.[0];
  if (entry === undefined) {
    for (const candidate of DEFAULT_ENTRIES) {
      if (await read.exists(candidate)) {
        entry = candidate;
        break;
      }
    }
  }

  // ── 钩子 ──
  const hooksPath = paths.hooks?.[0] ?? DEFAULT_HOOKS_PATH;
  let hooks: readonly ResolvedHookGroup[] = [];
  try {
    const hooksText = await read.read(hooksPath);
    if (hooksText !== undefined) hooks = resolveHooks(hooksText, uses, err, warn);
  } catch (error) {
    // 读不了 ≠ 不存在。前者要吼（可能是有意藏起来的东西），后者是常态。
    err('E9', `${hooksPath} 读不了：${message(error)}`);
  }

  // ── W6/W7 这两条不查格式，查的是"照这么写会不work" ──
  const covers = (pattern: string): boolean =>
    uses.some(
      (item) => item === '*' || item === pattern || (item.endsWith('.*') && pattern.startsWith(item.slice(0, -1))),
    );
  if (covers('tool.describe') && !covers('tool.call')) {
    warn('W6', 'uses 里有 tool.describe 却没有 tool.call —— 描述了一个不会执行的工具');
  }
  if (covers('tool.call') && !covers('tool.check')) {
    warn('W7', 'uses 里有 tool.call 却没有 tool.check —— 这个工具会被 confirm 当未知工具拒掉');
  }

  // ── W9 装了什么都不做 ──
  if (entry === undefined && hooks.length === 0) {
    warn('W9', '既没有入口模块、也没有可跑的钩子 —— 这个插件装上什么都不做');
  }

  const ok = !problems.some((problem) => problem.level === 'error');
  return {
    problems,
    ok,
    manifest: ok && name !== undefined
      ? {
          name,
          version: typeof rawVersion === 'string' ? rawVersion : '0.0.0',
          description: typeof record.description === 'string' ? record.description : undefined,
          homepage: typeof record.homepage === 'string' ? record.homepage : undefined,
          author: typeof rawAuthor === 'string' ? rawAuthor : undefined,
          uses,
          paths,
        }
      : undefined,
    entry,
    hooks,
  };
}

/**
 * 把一份 `hooks.json` 归一成"要跑什么"。
 *
 * `uses` 传进来只有一个用途：**W10** —— 钩子桥到的那个引擎事件没在 `uses` 里声明。
 * 这个插件在装载期会被整个撤掉（§4.3 按事件名查越界），而装载期的失败是
 * "插件看起来装了、实际一条都没生效"，最难查。所以在校验期就点名。
 */
function resolveHooks(
  text: string,
  uses: readonly string[],
  err: (code: string, message: string) => void,
  warn: (code: string, message: string) => void,
): readonly ResolvedHookGroup[] {
  let raw: unknown;
  try {
    raw = JSON.parse(text);
  } catch (error) {
    err('E9', `hooks.json 不是合法 JSON：${message(error)}`);
    return [];
  }
  if (typeof raw !== 'object' || raw === null || Array.isArray(raw)) {
    err('E9', 'hooks.json 顶层不是一个对象');
    return [];
  }

  const record = raw as Record<string, unknown>;
  // 两种形态都收：带包装的（插件的 `{description, hooks}`）与不带的（设置的 `{事件: [...]}`）。
  // 参考实现里这两种格式都真实存在，收下它俩的成本是一个 typeof。
  const body =
    typeof record.hooks === 'object' && record.hooks !== null && !Array.isArray(record.hooks)
      ? (record.hooks as Record<string, unknown>)
      : record;

  const out: ResolvedHookGroup[] = [];

  for (const [event, value] of Object.entries(body)) {
    if (event === 'description' && body === record) {
      // 直接形态里出现 description：多半是照着包装形态抄漏了一层。点名，别静默。
      warn('W1', 'hooks.json 里有 description 却没有外层 hooks 包装 —— 这一项被忽略');
      continue;
    }
    if (!isClassicEvent(event)) {
      err('E10', `hooks.json 里的 ${JSON.stringify(event)} 不是 classic 事件名（共 33 个）`);
      continue;
    }
    if (!isBridged(event)) {
      warn(
        'W3',
        `${event} 本版本不跑（只桥接了 PreToolUse / SessionStart / SessionEnd），这一节被跳过`,
      );
      continue;
    }
    // 桥得到 → 这个事件会去 `uses` 里查越界。查不到就撤掉**整个插件**，
    // 而那听起来像"装上了"—— 所以在这里就说破（W10，spec §2.3）。
    const bridged = BRIDGED_EVENTS[event];
    const declared =
      uses.includes(bridged) ||
      uses.includes('*') ||
      (bridged.startsWith('tool.') && uses.includes('tool.*'));
    if (!declared) {
      warn(
        'W10',
        `hooks.json 里有 ${event}，要桥到 ${bridged}，但清单的 uses 里没有声明它 —— ` +
          '装载时这个插件会被整个撤掉，请把 ' + bridged + ' 加进 uses',
      );
    }
    if (!Array.isArray(value)) {
      err('E11', `${event} 的值必须是数组`);
      continue;
    }

    for (const [index, group] of value.entries()) {
      if (typeof group !== 'object' || group === null || Array.isArray(group)) {
        err('E11', `${event}[${index}] 不是一个对象`);
        continue;
      }
      const entry = group as Record<string, unknown>;

      const defs = entry.hooks;
      if (!Array.isArray(defs) || defs.length === 0) {
        err('E11', `${event}[${index}].hooks 必须是非空数组`);
        continue;
      }

      // matcher：`*` 或没写 = 对所有工具生效；其余走 parseMatcher 的三档。
      let tools: readonly string[] | undefined;
      const matcher = entry.matcher;
      if (matcher !== undefined) {
        if (typeof matcher !== 'string') {
          err('E11', `${event}[${index}].matcher 必须是字符串`);
          continue;
        }
        const parsed = parseMatcher(matcher);
        if (parsed === 'regex') {
          warn(
            'W5',
            `${event} 的 matcher ${JSON.stringify(matcher)} 是正则形态，本版本不支持 —— 这一整组被跳过（不放大到所有工具）`,
          );
          continue;
        }
        tools = parsed === '*' ? undefined : parsed;
      }

      const resolved: ResolvedHookDef[] = [];
      for (const [defIndex, def] of defs.entries()) {
        const where = `${event}[${index}].hooks[${defIndex}]`;
        if (typeof def !== 'object' || def === null || Array.isArray(def)) {
          err('E11', `${where} 不是一个对象`);
          continue;
        }
        const item = def as Record<string, unknown>;

        const strayKeys = Object.keys(item).filter(
          (key) => key !== 'type' && key !== 'command' && key !== 'timeout',
        );
        if (strayKeys.length > 0) {
          warn('W2', `${where} 有未识别的字段：${strayKeys.join('、')}（本版本忽略）`);
        }

        if (item.type !== undefined && item.type !== 'command') {
          warn('W4', `${where} 的 type 是 ${JSON.stringify(item.type)}，本版本只支持 command 型 —— 跳过`);
          continue;
        }
        if (typeof item.command !== 'string' || item.command.trim() === '') {
          err('E13', `${where} 缺少 command（非空字符串）`);
          continue;
        }

        let timeoutMs = DEFAULT_HOOK_TIMEOUT_S * 1000;
        if (item.timeout !== undefined) {
          const seconds = item.timeout;
          if (
            typeof seconds !== 'number' ||
            !Number.isInteger(seconds) ||
            seconds < 1 ||
            seconds > MAX_HOOK_TIMEOUT_S
          ) {
            err(
              'E14',
              `${where} 的 timeout 必须是 1..${MAX_HOOK_TIMEOUT_S} 的整数（秒），实际是 ${JSON.stringify(seconds)}`,
            );
            continue;
          }
          timeoutMs = seconds * 1000;
        }

        resolved.push({ command: item.command, timeoutMs });
      }

      if (resolved.length > 0) out.push({ event, tools, hooks: resolved });
    }
  }

  return out;
}
```

> 注：`resolveHooks` 的签名里那两个回调（`err` / `warn`）是 `validatePlugin` 里那两个闭包的
> **传参形式**，不是另开的日志通道 —— 问题必须汇总到同一个 `problems` 数组里，
> 否则 `plugin validate` 的输出顺序会随调用路径变化。

```ts
import { spawn } from 'node:child_process';

import type { ResolvedHookDef } from '../contract/classic';

/**
 * classic 钩子的执行面 —— 全项目**唯一**一处 `spawn`。
 *
 * 分两个函数：`runHook` 只管跑与收集（IO），`classify` 只管把结果读成判定（纯函数）。
 * 分开是为了判定能被穷举测试 —— "退出码 2 拦住了"这条出口标准要是只能靠起进程验，
 * 就永远只能测到几条幸运路径。
 */

export type HookRun = {
  /** 退出码。`-1` = 根本没跑起来（起不来、超时、被信号杀）。 */
  readonly exitCode: number;
  readonly stdout: string;
  readonly stderr: string;
  /** 起不来 / 超时 / 被信号杀的原因。有它一律 deny。 */
  readonly failure: string | undefined;
};

/** 输出上限。一个往 stdout 灌无限数据的钩子不该让 CLI 吃光内存。 */
const OUTPUT_CAP = 64 * 1024;

export type HookContext = {
  /** 起钩子的工作目录。今天与 `projectDir` 同值（root = cwd），分开写是为了不让这个巧合变成前提。 */
  readonly cwd: string;
  /** 插件自己的目录：`${CLAUDE_PLUGIN_ROOT}` 指向它。 */
  readonly pluginRoot: string;
  readonly projectDir: string;
  readonly env: NodeJS.ProcessEnv;
};

export type HookVerdict =
  /** 没意见。链交给下层。 */
  | { readonly kind: 'silent' }
  /**
   * 有意见。`allow` **也如实报出来** —— 抹平（第三方不许放行）发生在桥里
   * （`classic-hooks.ts`），不在这里。分类器只负责读，不负责定政策，
   * 于是"钩子说了什么"与"我们采纳哪部分"是两件可以分别测的事。
   */
  | { readonly kind: 'say'; readonly decision: 'allow' | 'ask' | 'deny'; readonly reason: string | undefined }
  /** exit 2：拦住，理由给模型看。 */
  | { readonly kind: 'block'; readonly reason: string }
  /** 其余一切（exit 1/3/…、超时、起不来、判定读不出来）：一律 deny。 */
  | { readonly kind: 'fail'; readonly reason: string };

const DECISIONS: ReadonlySet<string> = new Set(['allow', 'ask', 'deny']);

function message(error: unknown): string {
  return error instanceof Error ? error.message : String(error);
}

/**
 * 展开命令里的 `${VAR}`。
 *
 * 不认识的变量**原样留着**，交给 shell 自己去处理 —— 换成空串的话，
 * 一个写错了变量名的钩子会变成一条语义完全不同的命令，而且没人看得出来。
 */
export function expandHookCommand(command: string, vars: Readonly<Record<string, string>>): string {
  return command.replace(/\$\{([A-Za-z_][A-Za-z0-9_]*)\}/g, (whole, name: string) => vars[name] ?? whole);
}

function cap(text: string): string {
  if (text.length <= OUTPUT_CAP) return text;
  return `${text.slice(0, OUTPUT_CAP)}\n…（输出被截断，超过 ${OUTPUT_CAP} 字符）`;
}

/**
 * 跑一个钩子。
 *
 * `shell: true`：命令是**用户自己写的 shell 片段**（`node guard.mjs && echo ok`），
 * 不当参数数组解析。与 `$.process.run` 同一个取向。
 */
export async function runHook(
  def: ResolvedHookDef,
  input: unknown,
  context: HookContext,
): Promise<HookRun> {
  let payload: string;
  try {
    payload = JSON.stringify(input);
  } catch (error) {
    return { exitCode: -1, stdout: '', stderr: '', failure: `钩子输入转不成 JSON：${message(error)}` };
  }

  const vars: Record<string, string> = {
    // 参考实现的名字 + 我们自己的名字，两组都给：照着文档写的钩子与照着 README 写的钩子都能跑。
    CLAUDE_PLUGIN_ROOT: context.pluginRoot,
    DEEPCODE_PLUGIN_ROOT: context.pluginRoot,
    CLAUDE_PROJECT_DIR: context.projectDir,
    DEEPCODE_PROJECT_DIR: context.projectDir,
  };
  // 参考实现还有个 CLAUDE_ENV_FILE（一个可以写环境变量的文件），
  // 我们**不设也不写**，如实缺着 —— 见设计 §11。用了它的钩子会拿到空字符串，与未定义同效。
  const env: NodeJS.ProcessEnv = { ...context.env, ...vars };

  return await new Promise<HookRun>((resolve) => {
    let stdout = '';
    let stderr = '';
    let failure: string | undefined;
    let settled = false;

    const child = spawn(expandHookCommand(def.command, vars), {
      cwd: context.cwd,
      env,
      shell: true,
      windowsHide: true,
    });

    const finish = (exitCode: number): void => {
      if (settled) return;
      settled = true;
      clearTimeout(timer);
      resolve({ exitCode, stdout: cap(stdout), stderr: cap(stderr), failure });
    };

    const timer = setTimeout(() => {
      failure = `超过 ${def.timeoutMs / 1000} 秒没结束，已杀掉`;
      // SIGKILL 不用来"请它体面退出"：钩子冻住主流程时，宽限期是奢侈品。
      // 与 $.process.run 的取向一致。
      child.kill('SIGKILL');
    }, def.timeoutMs);

    child.stdout?.on('data', (chunk: Buffer) => {
      stdout += chunk.toString('utf8');
    });
    child.stderr?.on('data', (chunk: Buffer) => {
      stderr += chunk.toString('utf8');
    });
    child.on('error', (error: Error) => {
      failure = `起不来：${error.message}`;
      finish(-1);
    });
    child.on('close', (code, signal) => {
      if (failure === undefined && signal !== null) failure = `被信号 ${signal} 干掉`;
      finish(code ?? -1);
    });

    if (child.stdin) {
      // 不读 stdin 的钩子会让这次写变成 EPIPE。那是它的事，不是我们的错，
      // 但没人接的 'error' 事件在 Node 里是**抛异常**。
      child.stdin.on('error', () => {});
      child.stdin.end(payload);
    }
  });
}

/**
 * 把一次执行读成判定。
 *
 * 三个有定义的结果：`exit 0`（silent / say）、`exit 2`（block）。
 * 其余一切 —— 别的退出码、超时、起不来、判定值读不出来 —— **一律 fail**。
 * 这条方向不能反：一个坏掉的钩子必须让动作停下来，不能让它悄悄通过（设计 §7）。
 */
export function classify(result: HookRun): HookVerdict {
  if (result.failure !== undefined) return { kind: 'fail', reason: result.failure };
  if (result.exitCode === 2) {
    const reason = result.stderr.trim();
    return { kind: 'block', reason: reason === '' ? '钩子以退出码 2 拦下，但没有给出理由' : reason };
  }
  if (result.exitCode !== 0) {
    return { kind: 'fail', reason: `钩子以退出码 ${result.exitCode} 结束（只有 0 与 2 是有定义的结果）` };
  }

  // exit 0：stdout 可能是纯文本，也可能是带判定的 JSON。读不出来就当它没意见 ——
  // 纯文本本来就是这样用的（往转录里写一行说明）。
  let parsed: unknown;
  try {
    parsed = JSON.parse(result.stdout);
  } catch {
    return { kind: 'silent' };
  }
  if (typeof parsed !== 'object' || parsed === null) return { kind: 'silent' };

  const record = parsed as Record<string, unknown>;
  const inner = record.hookSpecificOutput;
  const holder =
    typeof inner === 'object' && inner !== null ? (inner as Record<string, unknown>) : record;
  const decision = holder.permissionDecision ?? record.permissionDecision;
  if (decision === undefined) return { kind: 'silent' };

  if (typeof decision !== 'string' || !DECISIONS.has(decision)) {
    // 说不认识的话 ≠ 没意见。读不出来就 deny —— 与"退出码只认 0 与 2"同一条方向。
    return { kind: 'fail', reason: `钩子给的判定读不出来：${JSON.stringify(decision)}` };
  }

  const rawReason = holder.permissionDecisionReason ?? record.permissionDecisionReason;
  const reason = typeof rawReason === 'string' && rawReason.trim() !== '' ? rawReason : undefined;
  return { kind: 'say', decision: decision as 'allow' | 'ask' | 'deny', reason };
}
```

```ts
import { BRIDGED_EVENTS, type ResolvedHookGroup } from '../contract/classic';
import type { On } from '../contract/plugin';
import { classify, runHook, type HookContext, type HookVerdict } from './hook-run';

/**
 * 把 `hooks.json` 里的钩子组翻成链上的 hook。
 *
 * ⚠️ **这些 hook 是以那个插件自己的名字挂上去的**，不是由一个第一方"桥插件"代挂
 * （设计 §5.0）。差别是致命的：`uses` 越界检查与"剥掉 allow 判定"这两道闸都按
 * **插件名**生效 —— 代挂的话，这两道闸会作用在桥插件身上，于是一个插件只要把权限
 * 判定写进 `hooks.json` 就绕开了"只能更严"。代挂本身就是个漏洞。
 *
 * 落法：生产的 `plugin-dir.ts` 把 `hooks.json` 与入口模块拼成**一个** `Plugin`，
 * 两者共用同一个名字，于是共用同一块 `on`。这个文件只负责"拼什么"，不负责"谁去挂"。
 */

export type ClassicHooksDeps = {
  /** 插件名。只用于消息 —— 座位与闸门由名字在别处生效。 */
  readonly plugin: string;
  /** 插件目录：`${CLAUDE_PLUGIN_ROOT}` 指向它。 */
  readonly dir: string;
  readonly groups: readonly ResolvedHookGroup[];
  readonly cwd: string;
  readonly projectDir: string;
  readonly session: { readonly id: string; readonly transcriptPath: string | undefined };
  readonly env: NodeJS.ProcessEnv;
};

export function registerHooks(on: On, deps: ClassicHooksDeps): void {
  for (const group of deps.groups) {
    if (group.event === 'PreToolUse') {
      const check = makeCheck(deps, group);
      // matcher 是我们唯一的"多值"表达障碍：注册面只支持单键浅比较，
      // 于是 `Write|Edit` 挂成两条。任一命中即执行，同一时刻只会命中一条。
      if (group.tools === undefined) on('tool.check', check);
      else for (const tool of group.tools) on('tool.check', { tool }, check);
      continue;
    }
    // 剩下两个都是生命周期通知：桥接的目标定在 BRIDGED_EVENTS 里，不在这里写死。
    if (group.event === 'SessionStart') {
      on('session.start', makeNotifier(deps, group));
    } else {
      on('session.end', makeNotifier(deps, group));
    }
  }
}

function context(deps: ClassicHooksDeps): HookContext {
  return { cwd: deps.cwd, pluginRoot: deps.dir, projectDir: deps.projectDir, env: deps.env };
}

function makeCheck(deps: ClassicHooksDeps, group: ResolvedHookGroup) {
  return async ($: any, e: any, next: any) => {
    const input = {
      session_id: deps.session.id,
      transcript_path: deps.session.transcriptPath,
      cwd: deps.cwd,
      hook_event_name: 'PreToolUse',
      tool_name: e.tool,
      tool_input: e.input,
      // 参考实现的 stdin 里有这个字段，所以要填。它是 P3 唯一一处契约改动：
      // `tool.check` 的参数多了一个字段（**不是**新事件）—— loop 手里本来就有它。
      tool_use_id: e.toolUseId,
    };

    // 组内串行：前一条拦下就不再跑后一条。参考实现也是这个顺序，
    // 而"谁先拦下"决定了模型看到的理由是哪一句。
    for (const def of group.hooks) {
      const result = await runHook(def, input, context(deps));
      const verdict = classify(result);

      const said = result.stdout.trim();
      if (said !== '') $.ui.log(`[钩子 ${deps.plugin}] ${said}`);

      if (verdict.kind === 'block' || verdict.kind === 'fail') {
        return { decision: 'deny', rule: `${deps.plugin} 的钩子拦下了 ${String(e.tool)}：${verdict.reason}` };
      }
      if (verdict.kind === 'silent') continue;

      if (verdict.decision === 'allow') {
        // 第三方插件的 allow 一律不采纳（设计 §4.4）。这里**不是**把 allow 改写成 deny，
        // 而是当它没说过：下层（个人规则、confirm、fail-closed 链尾）照常裁决。
        // 差别在于"更严的永远赢"那个方向不受影响 —— 一个插件的 allow 连"让 confirm 闭嘴"
        // 都做不到，它做得到的只有"什么都不说"。
        $.ui.log(
          `[钩子 ${deps.plugin}] 想放行 ${String(e.tool)} —— 第三方插件只能拧紧不能拧松，这条判定被忽略，交给下层。`,
        );
        continue;
      }

      return { decision: verdict.decision, rule: reasonOf(deps, verdict, e) };
    }

    return next(e);
  };
}

function reasonOf(deps: ClassicHooksDeps, verdict: Extract<HookVerdict, { kind: 'say' }>, e: any): string {
  return `${deps.plugin} 的钩子要求${verdict.decision === 'ask' ? '先问一次' : '拒绝'} ${String(e.tool)}` +
    (verdict.reason === undefined ? '' : `：${verdict.reason}`);
}

function makeNotifier(deps: ClassicHooksDeps, group: ResolvedHookGroup) {
  return async ($: any, e: any, next: any) => {
    const input = {
      session_id: deps.session.id,
      transcript_path: deps.session.transcriptPath,
      cwd: deps.cwd,
      hook_event_name: group.event,
    };

    for (const def of group.hooks) {
      const result = await runHook(def, input, context(deps));
      const said = result.stdout.trim();
      if (said !== '') $.ui.log(`[钩子 ${deps.plugin}] ${said}`);
      const complained = result.stderr.trim();
      if (complained !== '') $.ui.notice(`[钩子 ${deps.plugin}] ${complained}`);
      // 这两个事件上**没有可阻断的动作** —— 会话已经开始了/已经在收了。
      // 所以退出码在这里只用来决定"要不要吭一声"，不改变任何裁决（设计 §5.3 的推论）。
      if (result.failure !== undefined) {
        $.ui.notice(`[钩子 ${deps.plugin}] 没跑成：${result.failure}（不影响主流程）`);
      } else if (result.exitCode !== 0 && result.exitCode !== 2) {
        $.ui.notice(`[钩子 ${deps.plugin}] 以退出码 ${result.exitCode} 结束（不影响主流程）`);
      }
    }

    return next(e);
  };
}
```

```ts
async function putPlugin(
  where: 'home' | 'root',
  world: { home: string; root: string },
  name: string,
  files: Record<string, string>,
): Promise<string> {
  const dir = join(world[where], '.deepcode', 'plugins', name);
  await mkdir(dir, { recursive: true });
  await writeFile(join(dir, 'plugin.json'), JSON.stringify({ name, version: '0.1.0', ...JSON.parse(files['plugin.json'] ?? '{}') }));

    if (relative === 'plugin.json') continue;
    await mkdir(join(dir, relative, '..'), { recursive: true });
    await writeFile(join(dir, relative), content);
  }
  return dir;
}
```

```ts
import { readdir, readFile, stat } from 'node:fs/promises';
import { join, resolve } from 'node:path';
import { pathToFileURL } from 'node:url';

import type { ResolvedHookGroup } from '../contract/classic';
import type { On, Plugin } from '../contract/plugin';
import { validatePlugin, type PluginManifest, type PluginReader } from '../contract/plugin-manifest';
import { registerHooks } from './classic-hooks';

/**
 * 插件目录的发现与装载。
 *
 * **两段，不是一个函数**，这是这个文件最要紧的结构：
 * - `discoverPlugins` 读清单（**不执行任何代码**）
 * - `installPlugins` import 入口（执行代码）
 *
 * `deepcode plugin list` 与 `validate` 只做前者。列个清单不该执行别人的代码 ——
 * 这条分界线让"看一眼"这个动作在安全上是平凡的。
 *
 * ⚠️ 而 `installPlugins` 里的那一行 `import` 就是"装一个插件 = 信任它"的全部。
 * 准入闸门管的是**链上权威**（谁能放宽权限），不是"这段代码能不能跑" ——
 * 把插件目录放进去，就是让它以你的身份跑。参考实现也是这个语义（设计 §4.6）。
 */

export type PluginOrigin = 'user' | 'project';

export type DiscoveredPlugin = {
  readonly name: string;
  readonly dir: string;
  readonly origin: PluginOrigin;
  readonly manifest: PluginManifest;
  /** 入口模块的相对路径。没有入口（只有钩子）时是 undefined。 */
  readonly entry: string | undefined;
  readonly hooks: readonly ResolvedHookGroup[];
};

export type SkippedPlugin = {
  readonly dir: string;
  readonly origin: PluginOrigin;
  /** 清单本身就坏时点不了名。 */
  readonly name: string | undefined;
  readonly reason: string;
};

export type Discovery = {
  /** 装得上的，按名字字典序。 */
  readonly loaded: readonly DiscoveredPlugin[];
  /** 没装的，每条带理由 —— `plugin list` 直接把这张表打出来。 */
  readonly skipped: readonly SkippedPlugin[];
};

export type DiscoverDeps = {
  readonly home: string;
  readonly root: string;
  /**
   * 项目级目录里哪几个被显式启用了（来自五层合并后的 `plugins.enable`）。
   * **用户级不受它管**：用户级一律自动装载 —— 那是"我自己装的插件"，
   * 与"这个仓库要求我装什么"是两件事（设计 §3）。
   */
  readonly enabled: readonly string[];
  readonly warn?: (line: string) => void;
};

const USER_DIR = ['.deepcode', 'plugins'] as const;

/**
 * 把一个插件目录包成 `PluginReader`。
 *
 * 只做拼接，不做边界检查 —— 越界的路径在校验器里就被 `isSafeRelativePath` 拦下了，
 * 这里只会收到通过检查的路径（外加清单校验器自己那几个字面量常量）。
 */
export function dirReader(dir: string): PluginReader {
  return {
    async read(relative) {
      // 与 settings.ts 的 TextReader 同一条区分：不存在返回 undefined 是常态，
      // 存在但读不了要抛 —— 后者可能是有人故意藏了个读不了的东西。
      try {
        return await readFile(join(dir, relative), 'utf8');
      } catch (error) {
        if ((error as NodeJS.ErrnoException | null)?.code === 'ENOENT') return undefined;
        throw error;
      }
    },
    async exists(relative) {
      try {
        await stat(join(dir, relative));
        return true;
      } catch {
        // 读不了也算"这儿没东西"：最坏的后果是报一条 E8「路径不存在」，
        // 而不会把"存在但读不了"悄悄放过去。
        return false;
      }
    },
  };
}

export async function discoverPlugins(deps: DiscoverDeps): Promise<Discovery> {
  const warn = deps.warn ?? (() => {});
  const projectDir = join(deps.root, ...USER_DIR);
  const userDir = join(deps.home, ...USER_DIR);

  // 项目级排前面：同名时用户级那份被丢掉。**项目级的赢**，因为"这个仓库要求用什么"，
  // 比"我全局装过什么"更具体 —— 与设置层的 project > user 同一个方向。
  const roots: readonly { origin: PluginOrigin; dir: string }[] =
    resolve(projectDir) === resolve(userDir)
      ? // home 兜底成 root 时两个目录是同一个（main.ts 的 home 默认值）。那种情况下
        // 按用户级算：它本来就是"我自己装的那个目录"，没有"这个仓库要求"可言。
        [{ origin: 'user', dir: userDir }]
      : [
          { origin: 'project', dir: projectDir },
          { origin: 'user', dir: userDir },
        ];

  const loaded: DiscoveredPlugin[] = [];
  const skipped: SkippedPlugin[] = [];
  const claimed = new Map<string, PluginOrigin>();

  for (const { origin, dir } of roots) {
    for (const name of await subdirectories(dir, warn)) {
      const pluginDir = join(dir, name);
      const validated = await validatePlugin(`插件目录 ${pluginDir}`, dirReader(pluginDir));

      for (const problem of validated.problems) {
        warn(`${problem.level === 'error' ? '✖' : '⚠'} ${pluginDir}：${problem.code} ${problem.message}`);
      }

      if (!validated.ok || validated.manifest === undefined) {
        const first = validated.problems.find((problem) => problem.level === 'error');
        skipped.push({
          dir: pluginDir,
          origin,
          name: undefined,
          reason: first === undefined ? '装不上' : `${first.code} ${first.message}`,
        });
        continue;
      }

      const manifest = validated.manifest;
      if (origin === 'project' && !deps.enabled.includes(manifest.name)) {
        skipped.push({
          dir: pluginDir,
          origin,
          name: manifest.name,
          reason: `项目级插件要显式启用：在 .deepcode/settings.json 里写 plugins.enable: ["${manifest.name}"]`,
        });
        continue;
      }

      const owner = claimed.get(manifest.name);
      if (owner !== undefined) {
        skipped.push({
          dir: pluginDir,
          origin,
          name: manifest.name,
          reason: `同名插件已由 ${owner} 级目录提供，这一份没用上`,
        });
        continue;
      }

      claimed.set(manifest.name, origin);
      loaded.push({
        name: manifest.name,
        dir: pluginDir,
        origin,
        manifest,
        entry: validated.entry,
        hooks: validated.hooks,
      });
    }
  }

  // 装载顺序 = 名字字典序。目录枚举顺序跨平台不保证，而"同 tier 内先装载者在外层"
  // 是条真规则 —— 用一个稳定的顺序换掉一个不稳定的顺序，让链的行为可预测。
  const byName = (a: { name: string }, b: { name: string }): number =>
    a.name < b.name ? -1 : a.name > b.name ? 1 : 0;
  return { loaded: loaded.sort(byName), skipped: skipped.sort((a, b) => (a.dir < b.dir ? -1 : a.dir > b.dir ? 1 : 0)) };
}

/** 目录不存在 = 没有插件（常态，不吭声）；在但读不了 = 这一层这次一个都不装，且要吼。 */
async function subdirectories(dir: string, warn: (line: string) => void): Promise<readonly string[]> {
  let entries: Awaited<ReturnType<typeof readdir>>;
  try {
    entries = await readdir(dir, { withFileTypes: true });
  } catch (error) {
    if ((error as NodeJS.ErrnoException | null)?.code === 'ENOENT') return [];
    warn(
      `插件目录 ${dir} 读不了（${error instanceof Error ? error.message : String(error)}）—— 这一层的插件这次一个都不装。`,
    );
    return [];
  }
  return entries
    .filter((entry) => entry.isDirectory())
    .map((entry) => entry.name)
    .sort();
}

export type InstallDeps = {
  /** 工作目录，也是 `${CLAUDE_PROJECT_DIR}`。今天等于会话根目录，分开写是为了不让巧合变成前提。 */
  readonly projectDir: string;
  readonly session: { readonly id: string; readonly transcriptPath: string | undefined };
  readonly env: NodeJS.ProcessEnv;
  readonly warn?: (line: string) => void;
};

/**
 * 把发现的插件变成真的 `Plugin`：入口模块与 `hooks.json` 在这里合流。
 *
 * 合流的意义不只是方便：两者共用**一个插件名、一个 `register`**，于是也共用
 * `uses` 检查与"剥掉 allow"那两道闸（设计 §5.0）。
 */
export async function installPlugins(
  discovered: readonly DiscoveredPlugin[],
  deps: InstallDeps,
): Promise<readonly Plugin[]> {
  const warn = deps.warn ?? (() => {});
  const out: Plugin[] = [];

  for (const item of discovered) {
    let entryRegister: ((on: On) => void) | undefined;

    if (item.entry !== undefined) {
      const file = join(item.dir, item.entry);
      try {
        const loaded = (await import(pathToFileURL(file).href)) as { default?: unknown };
        entryRegister = readRegister(loaded.default, item.name, warn);
      } catch (error) {
        warn(
          `插件 ${item.name} 的入口 ${file} 装不上（${error instanceof Error ? error.message : String(error)}）—— 整个插件不装。`,
        );
        continue;
      }
      // 入口在但不合格：readRegister 已经吼过，整个插件不装 —— 没有半个插件。
      if (entryRegister === undefined) continue;
    }

    out.push({
      name: item.name,
      uses: item.manifest.uses,
      register(on) {
        entryRegister?.(on);
        registerHooks(on, {
          plugin: item.name,
          dir: item.dir,
          groups: item.hooks,
          cwd: deps.projectDir,
          projectDir: deps.projectDir,
          session: deps.session,
          env: deps.env,
        });
      },
    });
  }

  return out;
}

/** 入口模块的默认导出必须是个带 `register` 函数的对象。其余一律装不上。 */
function readRegister(
  value: unknown,
  name: string,
  warn: (line: string) => void,
): ((on: On) => void) | undefined {
  if (typeof value !== 'object' || value === null) {
    warn(`插件 ${name} 的入口没有默认导出对象（要 \`export default { register }\`）。`);
    return undefined;
  }
  const module = value as Record<string, unknown>;
  if (typeof module.register !== 'function') {
    warn(`插件 ${name} 的入口对象上没有 register 函数。`);
    return undefined;
  }
  // 自述的名字被点名，但**以清单为准**：名字决定座位归属与 uses 判定，
  // 不能让被审对象自己说我是谁（设计 §2.2）。
  if (module.name !== undefined && module.name !== name) {
    warn(`插件 ${name} 的入口自述名字是 ${JSON.stringify(module.name)} —— 以清单为准，名字不能自述。`);
  }
  const register = module.register as (this: unknown, on: On) => void;
  // 用 .call(module)：插件把 register 写成方法、里头用 this 的话，剥出来单调用会当场炸。
  return (on) => register.call(module, on);
}
```

```ts
  /**
   * 撤回某个插件的全部注册，返回撤掉的条数。
   *
   * 给第三方插件的 `uses` 越界用：越界即**整个插件不装**（设计 §4.3）。
   * 只丢越界那一条的话，插件里其余部分会半死不活地继续生效 ——
   * 而人对"我写了五条规则"的心智模型是"要么都生效要么都不生效"。
   *
   * `pluginOrders` 里那个槽位**不动**：它只是个排序序号，留着不影响别人；
   * 而且同一个插件也不会再注册了 —— 它的 `on` 已经被封。
   */
  revoke(plugin: string): number {
    let removed = 0;
    for (let i = this.regs.length - 1; i >= 0; i--) {
      if (this.regs[i]?.plugin === plugin) {
        this.regs.splice(i, 1);
        removed += 1;
      }
    }
    return removed;
  }
```

- [ ] **Step 5: 写 `src/core/third-party.ts`**

```ts
import type { EventHook, On } from '../contract/plugin';
import type { Tier } from '../contract/tier';
import type { Registry } from './registry';

/**
 * 第三方插件的 `on` —— 能力上限在**结构上**被钉死：它没法放宽任何一行权限。
 *
 * 三件事，都在注册那一刻生效，不靠约定、不靠文档、不靠人记得：
 * 1. 返回的 `{decision:'allow'}` 一律丢弃（当它没说过，判定交回下层）
 * 2. 注册的事件必须在清单的 `uses` 里，越界就**整个插件不装**
 * 3. 往 `engine.create` 挂 hook 当场拒绝（不是静默无效 —— 那是颗地雷）
 *
 * 座位（永远 `append`）不在这里，在 `create.ts` 里强制 —— 它要在派发 `plugin.register`
 * 之前就定下来，而这次派发的结果本身就是闸门的一部分。
 */

export type ThirdPartyOnDeps = {
  readonly registry: Registry;
  readonly plugin: string;
  readonly tier: Tier;
  readonly uses: readonly string[];
  /** 装载期消息的出口（越界、拒挂 `$`）。生产里是 `coreNouns.logger.warn`。 */
  readonly log: (line: string) => void;
};

/**
 * `uses` 覆盖：`*` 覆盖一切，`tool.*` 覆盖 `tool.` 下的所有事件，否则精确匹配。
 *
 * 与 `registry.matchesPattern` 分开：那个是**事件名**匹配（运行时按 dispatch 的事件挑
 * hook），这个是**声明**匹配（装载期按 `uses` 挑注册）。两者规则像，但一个管链、
 * 一个管准入 —— 合成一个函数会让"改链的匹配"顺手改掉"准入的匹配"。
 */
export function coversUses(pattern: string, uses: readonly string[]): boolean {
  return uses.some(
    (item) =>
      item === '*' || item === pattern || (item.endsWith('.*') && pattern.startsWith(item.slice(0, -1))),
  );
}

function isAsyncIterable(value: unknown): boolean {
  return (
    typeof value === 'object' &&
    value !== null &&
    typeof (value as AsyncIterable<unknown>)[Symbol.asyncIterator] === 'function'
  );
}

export function makeThirdPartyOn(deps: ThirdPartyOnDeps): On {
  /** 越界之后这块 `on` 就废了：后续注册一概不理（先前那些已经被 revoke 撤掉）。 */
  let revoked = false;

  /**
   * 那道闸：**看返回值的形状**，不看 pattern 的名字。
   *
   * ⚠️ 这里与设计 §4.4 的初稿不同，是有意的纠正。初稿写的是"pattern 命中
   * `turn.step` 就跳过包装"，理由是外面套 async 会把生成器协议截断。两个问题：
   *
   * 1. 那个理由是错的。`dispatch` 用 `await Promise.resolve(hook(...))` 接返回值，
   *    而 `await` 一个生成器对象得到的还是它自己 —— async 包装**不破坏**生成器协议。
   * 2. 更要紧的是它是条**绕过路径**：`on('*')` 与 `on('tool.*')` 都命中 `turn.step`，
   *    于是通配 hook 会拿到"免包装"待遇，一条 `{decision:'allow'}` 就能溜出去。
   *
   * 改成无条件包装 + 按返回值的形状让流式直通：这一步之后，"想放宽"这件事
   * 不是被禁掉了，而是**没法表达** —— 一个第三方 hook 的 allow 连它自己那一层
   * 都出不去。
   */
  const wrap = (hook: EventHook): EventHook => {
    return ($, e, next) => {
      const returned = hook($, e, next);
      // 流式返回值在包装之前就原样交出去。今天内核里没有任何 hook 从钩子点返回
      // 生成器（`turn.step` 的应答者返回的是 `{}`），所以这一支是**守着一个假设**，
      // 不是一条承重路径 —— 留着它是因为它便宜，而去掉它需要"未来不会有流式 hook"这个承诺。
      if (isAsyncIterable(returned)) return returned;

      return (async () => {
        const out = await returned;
        if (isAsyncIterable(out)) return out;
        if (
          typeof out === 'object' &&
          out !== null &&
          (out as { decision?: unknown }).decision === 'allow'
        ) {
          const tool = (e as { tool?: unknown }).tool;
          // 走 ui 而不是 logger：这是**用户该看见的**事（有个插件想放行某个动作）。
          // 安全相关的反馈不该只活在 DEEPCODE_DEBUG 里。
          $.ui.log(
            `[插件] ${deps.plugin} 想放行${typeof tool === 'string' ? ` ${tool}` : ''} —— 第三方插件只能拧紧不能拧松，这条判定被丢弃，交给下层。`,
          );
          return next(e);
        }
        return out;
      })();
    };
  };

  const on = ((pattern: string, second: unknown, third?: unknown) => {
    if (revoked) return;

    const hook = (third ?? second) as EventHook;
    const matcher = third === undefined ? undefined : (second as Record<string, unknown>);

    if (pattern === 'engine.create') {
      // 今天这是个**静默无效**：`engine.create` 早在插件注册之前就折叠完了，
      // 挂上去的 hook 永远不会跑，而插件会以为自己扩展了 `$`（MVP §10 偏差 7）。
      // 静默无效比明着不支持坏得多 —— 改成当场拒绝，让它自己知道。
      deps.log(
        `[插件] ${deps.plugin} 想扩展 $（往 engine.create 挂 hook）—— 本版本不支持，这条注册被丢弃（插件扩展 $ 排在 P4）。`,
      );
      return;
    }

    if (!coversUses(pattern, deps.uses)) {
      revoked = true;
      const removed = deps.registry.revoke(deps.plugin);
      deps.log(
        `[插件] ${deps.plugin} 注册了 ${pattern}，但清单里的 uses 只有 ${deps.uses.length === 0 ? '（空）' : deps.uses.join('、')} —— 越界，整个插件不装（已撤掉 ${removed} 条注册）。`,
      );
      return;
    }

    deps.registry.register({ plugin: deps.plugin, tier: deps.tier, pattern, matcher, hook: wrap(hook) });
  }) as On;

  return on;
}
```

```ts
import type { Plugin } from '../contract/plugin';

/**
 * 准入闸门：应答 `plugin.register`。
 *
 * MVP 里这个钩子点就有，应答的是内核里一行 `() => ({ allow: true })`，
 * 注释写着"路径已经存在，P3 只需要换掉这个函数的实现"。这个文件就是那一步。
 *
 * 判定依据是**五层 settings 合并出来的 `plugins.deny`**：没有来源优先级，
 * 因为它只能关掉东西、永远不可能放宽 —— 于是"谁写的"对结果毫无影响（设计 §3）。
 *
 * 它坐 `prepend`：闸门在所有人前面，与 `sec-default` 同一个理由 ——
 * 它要能推翻下游，就不能坐在下游。
 *
 * ⚠️ 它拦的是**链上权威**，不是代码执行。装一个插件 = 信任它，这一点写在
 * `plugin-dir.ts` 里。这条闸门管的只是"装上来之后它能说什么话"。
 */
export type PluginDenyRule = {
  readonly name: string;
  /** 规则来自哪一层（`user` / `project` / `local` / `flag` / `policy`）。只用来把理由说清。 */
  readonly source: string;
};

export type PluginGuardDeps = {
  readonly deny: readonly PluginDenyRule[];
  /**
   * 第一方（CLI 自带）插件的名字。名单点到它们时忽略并点名。
   *
   * 一份托管策略里写 `deny: ["sec-default"]` 多半是写错了 —— 而它的后果是
   * **守门器不装**，也就是整套权限模型的承重墙被托管方自己拆了。
   * 一份"禁用名单"不该有这个能力。
   */
  readonly firstParty: readonly string[];
};

export function createPluginGuardPlugin(deps: PluginGuardDeps): Plugin {
  return {
    name: 'plugin-guard',
    uses: ['plugin.register', 'ui'],

    register(on) {
      on('plugin.register', async ($, e, next) => {
        const hit = deps.deny.find((rule) => rule.name === e.name);
        if (hit === undefined) return next(e);

        if (deps.firstParty.includes(e.name)) {
          $.ui.log(
            `[插件] 禁用名单里点名了第一方插件 ${e.name}（规则来自 ${hit.source} 层）—— 忽略。这份名单是给掉进目录的第三方插件设的闸，不是拆承重墙的开关。`,
          );
          return next(e);
        }

        return { refuse: `被禁用（规则来自 ${hit.source} 层 settings 的 plugins.deny）` };
      });
    },
  };
}
```

**(f) 新增 `readPlugins`**（放在 `readLayer` 之后）：

```ts
/**
 * 解析一层的 `plugins` 段。
 *
 * 形状错的处置与 `permissions` 完全一致：**整份废掉这一层**，不是丢掉坏的那一项 ——
 * 类型不对说明写的人以为它生效了，只丢一半的话他会看到"文件被读进去了"。
 * 名字格式不对则是单条不生效（方向是不收紧），但必须吼。
 */
function readPlugins(
  value: unknown,
  layer: Layer,
  where: string,
  warn: (line: string) => void,
): { readonly value: PluginsLayer } | { readonly broken: string } {
  if (value === undefined) return { value: EMPTY_PLUGINS };
  if (typeof value !== 'object' || value === null || Array.isArray(value)) {
    return { broken: 'plugins 不是一个对象' };
  }

  const record = value as Record<string, unknown>;
  const out: { enable: string[]; deny: string[] } = { enable: [], deny: [] };

  for (const key of ['enable', 'deny'] as const) {
    const list = record[key];
    if (list === undefined) continue;
    if (!Array.isArray(list)) return { broken: `plugins.${key} 不是数组` };

    const bad = list.findIndex((item) => typeof item !== 'string');
    if (bad !== -1) return { broken: `plugins.${key}[${bad}] 不是字符串` };

    for (const name of list as string[]) {
      if (!isPluginName(name)) {
        warn(
          `${label(layer.source)} ${where} 这条不生效 —— plugins.${key}: ${JSON.stringify(name)} 不是 kebab-case 的插件名。`,
        );
        continue;
      }
      if (key === 'enable' && !PLUGIN_ENABLE_SOURCES.includes(layer.source as never)) {
        warn(
          layer.source === 'user'
            ? `${label(layer.source)} ${where} 这条不生效 —— plugins.enable 不认 user 层（用户级插件本来就自动装载）。`
            : `${label(layer.source)} ${where} 这条不生效 —— plugins.enable 不认托管层（托管策略只该能收紧，不该替你打开一个插件）。`,
        );
        continue;
      }
      out[key].push(name);
    }
  }

  const unknown = Object.keys(record).filter((key) => key !== 'enable' && key !== 'deny');
  if (unknown.length > 0) {
    warn(`${label(layer.source)} ${where} 的 plugins 里有不认识的子键：${unknown.join('、')}（已忽略）。`);
  }

  return { value: out };
}
```

```ts
    const read = await readLayer(layer, deps.home, warn, readText);
    sources.push(read.info);
    bySource.set(layer.source, read.rules);
    pluginsBySource.set(layer.source, read.plugins);
  }

  const withSource = (source: SettingsSource, names: readonly string[]): readonly PluginRule[] =>
    names.map((name) => ({ name, source }));

  return {
    sources,
    policyRules: bySource.get('policy') ?? [],
    personalRules: SETTINGS_SOURCES.filter((s) => s !== 'policy').flatMap((s) => bySource.get(s) ?? []),
    plugins: {
      enable: dedupe(
        PLUGIN_ENABLE_SOURCES.flatMap((source) =>
          withSource(source, pluginsBySource.get(source)?.enable ?? []),
        ),
      ),
      deny: dedupe(
        SETTINGS_SOURCES.flatMap((source) =>
          withSource(source, pluginsBySource.get(source)?.deny ?? []),
        ),
      ),
    },
  };
}

/** 按名字去重，保留先出现的那个来源。合并语义是并集，留谁都不改行为，只影响 /permissions 的显示。 */
function dedupe(rules: readonly PluginRule[]): readonly PluginRule[] {
  const seen = new Set<string>();
  const out: PluginRule[] = [];
  for (const rule of rules) {
    if (seen.has(rule.name)) continue;
    seen.add(rule.name);
    out.push(rule);
  }
  return out;
}
```

```ts
function parsePluginCommand(argv: readonly string[]): StartupAction | undefined {
  const first = argv.findIndex((arg) => !arg.startsWith('-'));
  if (first === -1 || argv[first] !== 'plugin') return undefined;

  const sub = argv[first + 1];
  if (sub === undefined) return { kind: 'plugin', sub: 'help' };
  if (sub === 'list') return { kind: 'plugin', sub: 'list' };
  if (sub === 'validate') {
    const dir = argv[first + 2];
    return dir === undefined ? { kind: 'plugin', sub: 'help' } : { kind: 'plugin', sub: 'validate', dir };
  }
  return undefined;
}
```

```ts
import { resolve } from 'node:path';

import type { PluginManifest, Problem } from '../contract/plugin-manifest';
import { validatePlugin } from '../contract/plugin-manifest';
import type { StartupAction } from './args';
import { dirReader, discoverPlugins, type Discovery } from './plugin-dir';

/**
 * `deepcode plugin list` 与 `deepcode plugin validate <目录>`。
 *
 * 两条都**不执行任何插件的代码** —— `discoverPlugins` 只读清单，`validatePlugin` 是纯逻辑。
 * 这条分界线不是洁癖：它让"看一眼这个插件是什么"在安全上是平凡的，而
 * `deepcode plugin list` 是第一个会被人对着一个陌生目录敲的命令。
 *
 * validate 会把 `hooks.json` 里的命令**原文**打出来。这不是装饰：装一个插件 =
 * 信任它（代码在你的进程里跑），而 validate 能做到的下限就是让你在装之前看见
 * 它想跑什么。看不见的信任不叫信任，叫不知情。
 */

export type PluginAction = Extract<StartupAction, { kind: 'plugin' }>;

export type PluginCommandDeps = {
  readonly action: PluginAction;
  readonly home: string;
  readonly root: string;
  /** 五层合并后的 `plugins.enable`（只有项目级的发现需要它）。 */
  readonly enabled: readonly string[];
  readonly out: (line: string) => void;
  readonly err: (line: string) => void;
};

/** 返回进程退出码 —— 子命令要能进脚本，所以失败必须有非零码。 */
export async function runPluginCommand(deps: PluginCommandDeps): Promise<number> {
  if (deps.action.sub === 'help') {
    deps.out(PLUGIN_HELP);
    return 0;
  }
  if (deps.action.sub === 'list') {
    const found = await discoverPlugins({
      home: deps.home,
      root: deps.root,
      enabled: deps.enabled,
      warn: deps.err,
    });
    deps.out(renderList(found, deps.home, deps.root));
    return 0;
  }

  const dir = resolve(deps.action.dir);
  const validated = await validatePlugin(dir, dirReader(dir));
  deps.out(renderValidate(dir, validated));
  return validated.ok ? 0 : 1;
}

export const PLUGIN_HELP = `deepcode plugin —— 插件

  deepcode plugin list             列出装上的与跳过的，各带理由
  deepcode plugin validate <目录>  只校验一份清单，不执行任何代码

装在哪
  用户级 ~/.deepcode/plugins/<名字>/plugin.json        自动装载
  项目级 <工作目录>/.deepcode/plugins/<名字>/plugin.json  要在设置里 plugins.enable 之后才装

一份插件至少要有 plugin.json（name / version），可以带一个入口模块（main.mjs）与
一份 hooks/hooks.json。清单里的路径必须是相对的、以 ./ 开头、不含 ..。
`;

function renderValidate(dir: string, validated: Awaited<ReturnType<typeof validatePlugin>>): string {
  const lines: string[] = [];
  const errors = validated.problems.filter((problem) => problem.level === 'error');
  const warns = validated.problems.filter((problem) => problem.level === 'warn');

  lines.push(`插件目录 ${dir}`);
  lines.push(
    validated.ok
      ? `清单没问题${warns.length === 0 ? '' : `（${warns.length} 条警告）`}`
      : `清单有问题：${errors.length} 条错误${warns.length === 0 ? '' : `、${warns.length} 条警告`}`,
  );
  lines.push(...renderProblems(validated.problems));

  if (validated.manifest) lines.push('', ...renderManifest(validated.manifest));
  if (validated.entry !== undefined) lines.push(`  入口模块     ${validated.entry}`);
  lines.push(...renderHooks(validated.hooks));
  lines.push('', '这份命令没有执行任何插件的代码 —— 只读了文件。');
  return lines.join('\n');
}

function renderList(found: Discovery, home: string, root: string): string {
  const lines: string[] = [`插件目录 ${root}/.deepcode/plugins 与 ${home}/.deepcode/plugins`];

  lines.push('', `装上来的（${found.loaded.length}）`);
  if (found.loaded.length === 0) lines.push('  （一个都没有）');
  for (const plugin of found.loaded) {
    const parts = [`${plugin.manifest.version}`, plugin.origin === 'user' ? '用户级' : '项目级'];
    if (plugin.entry !== undefined) parts.push(`入口 ${plugin.entry}`);
    if (plugin.hooks.length > 0) {
      parts.push(`钩子 ${plugin.hooks.map((group) => group.event).join('、')}`);
    }
    lines.push(`  ${plugin.name.padEnd(24)} ${parts.join(' · ')}`);
    if (plugin.manifest.description !== undefined) {
      lines.push(`  ${' '.repeat(24)} ${plugin.manifest.description}`);
    }
  }

  lines.push('', `跳过的（${found.skipped.length}）`);
  if (found.skipped.length === 0) lines.push('  （没有）');
  for (const skipped of found.skipped) {
    lines.push(`  ${(skipped.name ?? '（清单坏了）').padEnd(24)} ${skipped.reason}`);
    lines.push(`  ${' '.repeat(24)} ${skipped.dir}`);
  }

  lines.push('', '这份命令没有执行任何插件的代码 —— 只读了文件。');
  return lines.join('\n');
}

function renderProblems(problems: readonly Problem[]): readonly string[] {
  return problems.map(
    (problem) => `  ${problem.level === 'error' ? '✖' : '⚠'} ${problem.code} ${problem.message}`,
  );
}

function renderManifest(manifest: PluginManifest): readonly string[] {
  const lines = [`  名字         ${manifest.name}`, `  声明要用的   ${manifest.uses.length === 0 ? '（什么都没声明）' : manifest.uses.join('、')}`];
  if (manifest.description !== undefined) lines.push(`  说明         ${manifest.description}`);
  if (manifest.homepage !== undefined) lines.push(`  主页         ${manifest.homepage}`);
  return lines;
}

function renderHooks(hooks: Awaited<ReturnType<typeof validatePlugin>>['hooks']): readonly string[] {
  if (hooks.length === 0) return [];
  const lines = ['', '它会跑的命令'];
  for (const group of hooks) {
    const scope = group.tools === undefined ? '所有工具' : group.tools.join('、');
    for (const def of group.hooks) {
      lines.push(`  ${group.event}  [${scope}]  ${def.timeoutMs / 1000}s`);
      lines.push(`    ${def.command}`);
    }
  }
  return lines;
}
```

```ts
  // 2. session-changes 必须排在 coreTools **之前**：同 tier 内先装载者在外层，

  // 3. 第三方插件排在**最后**：它们坐 append，与这里的第一方同 tier 时后装载者在内层，

  const firstParty: Plugin[] = [

    createChangesPlugin(deps.changes),

  // 它就真的会被拦下（一份禁用名单从而又能拆承重墙了）。
  const names = firstParty.map((plugin) => plugin.name);
  const guard = createPluginGuardPlugin({ deny: deps.pluginDeny ?? [], firstParty: names });
  // 守门器放最前，但它坐在 `prepend` —— 上面那条"座位比顺序更重要"在这里同样成立。
  const discovered = deps.discovered ?? [];

  return {
    plugins: [
      guard,

    // 连这张表都钉不动它们 —— 见 core/create.ts。
    thirdParty: discovered.map((plugin) => plugin.name),
```

```js
/**
 * 从 stdin 读 PreToolUse 事件，看这次要写的内容里有没有密钥形状的东西。
 *
 * 有 → stderr 说清是哪一行、什么形状，退出码 2（classic 的"拦下"，理由会给模型看）。
 * 没有 → 退出码 0，一个字不说（"没意见"）。
 *
 * 只看**内容**，不看文件路径：路径判断是权限规则（deny: ["Write(./.env)"]）的事，
 * 插件不该重复实现一套，更不该因为路径看起来敏感就放行。
 */
let raw = '';
process.stdin.setEncoding('utf8');
process.stdin.on('data', (chunk) => {
  raw += chunk;
});
process.stdin.on('end', () => {
  let event;
  try {
    event = JSON.parse(raw);
  } catch {
    // 读不懂输入就别说"没问题"。退出码 1 = 非阻断错误，走过去。
    process.exit(1);
  }

  const input = event.tool_input ?? {};
  // Write 用 content，Edit 用 new_string。取不到就当空串 —— 一个扫不出东西的
  // 钩子不该误报。
  const text = typeof input.content === 'string' ? input.content
    : typeof input.new_string === 'string' ? input.new_string
    : '';
  if (text === '') process.exit(0);

  const patterns = [
    { name: 'Anthropic key', re: /sk-ant-[A-Za-z0-9_-]{20,}/ },
    { name: 'AWS access key', re: /AKIA[0-9A-Z]{16}/ },
    { name: 'PEM 私钥', re: /-----BEGIN [A-Z ]*PRIVATE KEY-----/ },
    { name: 'GitHub token', re: /gh[pousr]_[A-Za-z0-9]{36,}/ },
    { name: '写成字面量的口令', re: /(api[_-]?key|secret|password|passwd|token)\s*[:=]\s*['"][^'"\s]{12,}['"]/i },
  ];

  const hits = [];
  const lines = text.split(/\r?\n/);
  for (const [index, line] of lines.entries()) {
    for (const pattern of patterns) {
      if (pattern.re.test(line)) {
        // 只说形状与行号，**不回显那一行**：回显等于把密钥再抄一遍，
        // 而钩子的 stderr 会进模型上下文与转录文件。
        hits.push(`第 ${index + 1} 行看起来是${pattern.name}`);
        break;
      }
    }
  }

  if (hits.length === 0) process.exit(0);

  process.stderr.write(
    `这次写入里发现了 ${hits.length} 处密钥形状的内容：\n` +
      hits.map((hit) => `  ${hit}`).join('\n') +
      '\n（secret-guard 插件拦下了这次写入。真要写进去，请先把密钥换成占位符或从环境变量读。）\n',
  );
  process.exit(2);
});
```

```js
/**
 * 一个**不改引擎**的插件：加一个工具。
 *
 * 它一行内核代码都没碰 —— 工具清单来自注册面上 `tool.call` 的 matcher 取值
 * （`$.tool.list()` 就是这么实现的），所以"注册上来"就等于"模型看得见"。
 *
 * 它也不是特权：走的是与 Read / Write / Bash 完全相同的那两条事件
 * （`tool.describe` 说清参数、`tool.call` 干活），而权限判定由内核那一条
 * `tool.check` 链负责 —— 这个插件连问都不问，也没法替用户答。
 */
export default {
  register(on) {
    on('tool.describe', { tool: 'TodoWrite' }, () => ({
      description: '往当前工作目录的 .deepcode-todo.md 追加一条待办。',
      inputSchema: {
        type: 'object',
        properties: {
          item: { type: 'string', description: '待办内容（一句话）' },
        },
        required: ['item'],
      },
    }));

    on('tool.call', { tool: 'TodoWrite' }, async ($, e) => {
      // 模型给的东西一律当不可信输入：它可能给个对象、给个空串、给个数字。
      const input = e.input ?? {};
      const item = typeof input.item === 'string' ? input.item.trim() : '';
      if (item === '') return { deny: 'TodoWrite 需要 item（非空字符串）' };

      const path = `${$.session.cwd()}/.deepcode-todo.md`;
      let existing = '';
      try {
        existing = await $.fs.read(path);
      } catch {
        // 第一次用，文件还不存在。这不是错误。
      }
      const header = existing === '' ? '# 待办\n\n' : '';
      await $.fs.write(path, `${existing}${header}- [ ] ${item}\n`);
      return { value: `已记下：${item}` };
    });
  },
};
```

**两处与 spec 不同的落法**（写计划时已经回写进 spec，Task 12 Step 5 只做核对）

1. **§4.4 的包装判定**：spec 初稿按 pattern 名字（命中 `turn.step` 就跳过包装）决定要不要过那道闸。这是个**绕过路径** —— `on('*')` 与 `on('tool.*')` 同样命中 `turn.step`，于是通配 hook 拿到免检待遇。改成无条件包装 + 按返回值形状让流式直通。附带纠正：初稿说"外面套 async 会把生成器协议截断"是错的（`dispatch` 用 `await Promise.resolve(hook(...))` 接返回值，`await` 一个生成器得到的还是它自己）。
2. **§2.3 加 W10**：`hooks.json` 里桥接的事件没在 `uses` 里声明 —— 装的时候那个插件会被整个撤掉，所以在校验期就点名。同理（但方向相反）的 W6/W7 已在 spec 里，W10 是同一族里缺的那一条。

**两处计划层的取舍**（不改 spec 的语义）

1. **fixture 用临时目录现造**，不提交 `test/fixtures/plugins/`：`mkdtemp` + 现写文件让每个用例的现场就在它自己那一屏里，而提交一堆坏清单会变成"没人知道为什么这几个文件是坏的"。
2. **`classic.ts` 里定义 `DEFAULT_HOOK_TIMEOUT_S` / `MAX_HOOK_TIMEOUT_S`**，而不是放在校验器里：`ResolvedHookDef.timeoutMs` 是契约的一部分，默认值就该与它住在一起。

**占位符扫描**：没有 TBD / TODO / "类似 Task N" / "加上适当的错误处理"。每个改动代码的步骤都给了完整代码或完整的替换片段。

**类型一致性**：`Problem` / `PluginManifest` / `PluginReader` / `Validated` / `ResolvedHookGroup` / `ResolvedHookDef` / `DiscoveredPlugin` / `SkippedPlugin` / `Discovery` / `InstallDeps` / `HookRun` / `HookVerdict` / `HookContext` / `ClassicHooksDeps` / `PluginDenyRule` / `PluginRule` / `PluginsLayer` / `ThirdPartyOnDeps` / `PluginAction` / `PluginCommandDeps` 逐个在"定义处"与"使用处"对过名字与字段。几处容易错的：

- `makeThirdPartyOn` 的参数是**一个对象**（`ThirdPartyOnDeps`），Task 6 里 `create.ts` 的调用与定义一致。
- `discoverPlugins` 返回 `{ loaded, skipped }`，而 `installPlugins` 收的是 **`loaded` 数组**（不是整个 `Discovery`）—— Task 5 的测试与 Task 10 的 `main.ts` 都是这么调的。
- `registerHooks(on, deps)` **不是** `Plugin`：Task 5 把它包进 `Plugin.register`，Task 4 的测试也照这个样子包。
