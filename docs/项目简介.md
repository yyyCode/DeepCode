# DeepCode 项目简介

> 一个终端里的 agentic 编码助手。给它一句自然语言，它会读文件、改文件、跑命令。
> 用 TypeScript 从零写，**零运行时依赖**。

这份文档给第一次听说它的人：一页纸讲完「是什么、凭什么信它、现在到哪一步」。
细节在仓库根的 [README](../README.md) 与 [`superpowers/`](superpowers/) 里。

## 一句话

引擎在每个调用点抛出一个事件，插件把自己的 hook 注册成中间件，按 tier 权威序串成一条链：

```
prepend > user > append > builtin > core
```

一个 hook 可以**应答 / 改写 / 拒绝 / 委托下层**。`next(e)` 是 Koa 式续体，不是事件发射器 ——
不调 `next` 就是结束这条链并应答，调 `next({ ...e, field })` 就是带着改写往下走。
链尾只有一处，没有第二个地方可以漏。

于是「这个动作会不会被拦下、被谁拦下、拦下之后发生了什么」能在代码里指出来，不用读日志猜。

## 三个立得住的点

1. **一条链，没有特例。** 六个内建工具（`Read` / `Write` / `Edit` / `Bash` / `Glob` / `Grep`）
   与将来的第三方插件走**完全相同**的接口 —— 内核里没有一张硬编码的工具表；
   模型看得见的工具清单来自注册面上 `tool.call` 的 matcher 取值。
2. **边界由脚本守，不靠自觉。** `pnpm lint` 就是 `scripts/check-boundaries.mjs`：
   `contract/` 不许 import 任何东西，`builtins/` 只许 import `contract/`。
   往 `contract/` 里加一个 import，直接红。
3. **fail-closed 到底。** 非 TTY（管道、CI）默认拒绝；不认识的工具拒绝；
   `tool.check` 走到链尾无人应答也是 `deny`，不是 `allow`。方向一旦定成 fail-open，后面补不回来。

## 现在能做什么

- **六个工具**：读、写、改文件，跑命令，找文件（`Glob`），搜内容（`Grep`）。
  会写盘或执行命令的动作先打预览、停下等你按一次 `y`。
- **两种用法**：一次性 `deepcode "把测试跑一遍，失败的那条修掉"`，或者进去聊（REPL）。
- **会话**：转录落成 JSONL，`deepcode --resume` 接着上次继续（`--resume=<id>` 指定某一次）。
- **五个斜杠命令**：`/help` `/diff` `/clear` `/permissions` `/exit`。
- **换 provider 不用改代码**：`~/.deepcode/config.json` 里改 `apiKey` / `baseUrl` / `model` 三样，
  Anthropic 与任何 OpenAI 兼容端点都能接。
- **可配置的权限**：五层 settings + `allow` / `ask` / `deny` 规则，`/permissions` 看当前生效了什么。
- **插件**：用户级目录自动装载，项目级要显式启用。第三方插件只能拧紧不能拧松 ——
  它返回的放行判定会被丢弃，越界注册整个插件不装。`deepcode plugin list` 看装了哪些。

## 权限模型：谁能放宽，谁不能

设置来源从低到高五层：`user` < `project` < `local` < `flag` < `policy`（托管）。

- **更严的永远赢**：`deny > ask > allow`，与规则写在哪一层、在同一数组里排第几都无关 ——
  重排一下配置文件不会换行为。
- **托管策略掀不翻**：守门器跑完整条链后，若下游把策略的更严判定放宽了，直接拿策略原文推翻它。
  个人 `allow` 的效力上限，是把一次 `ask` 变成 `allow`。
- **刻意没有环境变量来源**：一个环境变量就能改权限，等于在规则引擎上开后门。
- **没有 `--yes`，也没有别的自动放行开关。** 非交互环境里没人能按 `y`，那就写不了文件、跑不了命令。
  谁加自动放行开关谁就是在开倒车。
- **`deny` 是给手滑与误操作加的一道闸，不是反对抗手段。** 规则比的是命令行的开头，
  `Bash(git push:*)` 拦得住 `git push origin main; rm -rf ~`，但拦不住 `true && git push origin main`。
  真要封死得靠进程权限或沙箱，那排在后面的阶段。

解析好的不可变数组，重放只会得到与第一遍相同的答案。守门器改成「持有裁决」比它更强 ——
偏差如实记在 [P2 计划](superpowers/plans/2026-10-11-deepcode-p2.md) 里。

事件目录：**39 个已声明，12 个已实现**，其余 27 个用到时会抛 `NotImplementedError`。
这是如实标注，不是「即将支持」。

## 已知限制（有意不做）

- **没有路径围栏**：能碰到你进程权限内的任何路径，不限工作目录。确认提示拦的是「要不要动手」，
  不是「动哪里」。所以别在装着重要东西的机器上放它乱跑。
- **中断只杀外壳**：Windows 上 `Bash` 经 `cmd.exe` 起命令，`Ctrl-C` 掐断的是这层外壳，
  下面的孙进程可能继续残留（没有进程组）。
- **没有 TUI、没有语法高亮**：有 ANSI 着色与单行 spinner，界面仍是逐行的纯文本流。
- **非 TTY 下 REPL 收不到输入**：`echo '/diff' | deepcode` 无效 —— readline 与主流程之间有一段
  空窗，管道里的行在那段空窗里被读掉扔了。要脚本化请用一次性模式。
- **托管策略文件存在却读不了时，那一层按空处理**（大声警告 + `/permissions` 标出来）。
  这是整个设计里唯一一条真正的 fail-open，且消不掉 —— 看到那行警告，就是此刻没有守护。
- **插件只桥了 3 个 classic 事件**（`PreToolUse` / `SessionStart` / `SessionEnd`）。参考实现有
  33 个事件名；其余 30 个在 `hooks.json` 里会被跳过并点名，不是静默忽略 —— 它们要的是我们
  还没有的钩子点。另外 `uses` 只在事件级别校验，细到 matcher 一级的声明排在 P4。
- **没有 CI、没有 LICENSE**。前者在设计里排到 MVP 之后，后者是未指定许可证（保留所有权利）。

## 快速开始

```bash
git clone https://github.com/yyyCode/DeepCode && cd DeepCode
pnpm install && npm link            # 需要 Node ≥ 20

mkdir -p ~/.deepcode                # 配 key（也可以用环境变量 ANTHROPIC_API_KEY）
cat > ~/.deepcode/config.json <<'EOF'
{ "apiKey": "sk-ant-..." }
EOF

cd /你的项目 && deepcode "跑一下测试，把失败的那条修掉"
```
